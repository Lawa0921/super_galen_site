# Caravan M50 — Combat Readability / 戰鬥預判與防禦語意

## 問題

M49 已經讓前後排真正影響近戰與遠程命中，但玩家若必須先按下招式、再從戰鬥紀錄看到 `命中 -2`，規則雖然公平，體驗仍然不是公平的。

另一個世界觀／語意問題是基礎守勢叫做「架盾」，攔截敘事也假定角色一定持盾；然而目前裝備 schema 沒有盾牌欄位，跨職武器與各種護甲也都允許使用守勢。把不存在的裝備寫進核心動作會讓系統規則與敘事互相矛盾。

## M50 修正

### 出手前就看見站位後果

玩家戰鬥 runtime 的招式名稱會直接顯示最短必要資訊：

- `重斬〔近戰〕`：目前站位適合近戰，沒有額外命中懲罰。
- `重斬〔近戰 -2〕`：目前站位會受到 M49 的近戰命中 -2。
- `疾射〔遠程〕`：目前有正常射界。
- `疾射〔遠程 -2〕`：目前承受近身壓力，命中 -2。
- 真正秘法／神術保留原本的學派與資源標籤，例如 `炎術・火球〔秘法 2〕`，不疊加物理距離文字。

標籤是 runtime 動態值，不是進入戰鬥時寫死。若 M49 的「前線崩潰」把後排成員推到前排，下一次 UI render 會立刻反映新的近戰／遠程狀態。

### 防禦語意不再假裝人人都有盾

玩家的基礎 `guard` 在戰鬥中改顯示：

- 前排：`防禦架勢〔護衛〕`
- 後排：`防禦架勢〔自保〕`

其機制不變：防禦 +4；只有前排守勢能替同伴攔截單體攻擊。玩家守勢的敘事改為「以武器與護具架起防禦」，不再假定角色裝備盾牌。

這不取消鐵壁衛等真正以盾牌為職業幻想的專精招式；修的是「所有角色的通用守勢都被當作持盾」這個語意錯誤。

## 為什麼不用額外 UI 面板

主冒險、餘燼朝聖、灰燼聖匣與裂旗護運目前都直接渲染 live `move.name`。M50 將可讀性做在共用戰鬥 runtime，而不是四頁各寫一套判斷，因此：

1. 不會出現某頁有提示、另一頁沒有的規則漂移。
2. 前線崩潰改變站位後，各頁都能在下一次 render 自動更新。
3. 魔法資源標籤仍由 M41/M44 arcana 單一來源負責。
4. M50 不改命中、傷害或資源公式，因此不引入新的數值乘區。

## 玩家視角多維度對抗審查

### 資訊公平性

任何實際受到 M49 `-2` 的 mundane attack，出手前的 live label 必須包含 `-2`。測試反向要求：若沒有實際懲罰，標籤不得出現 `-2`。

### 新手認知成本

按鈕只增加 `〔近戰〕`、`〔遠程〕`、`〔近戰 -2〕`、`〔遠程 -2〕`、`〔護衛〕` 或 `〔自保〕`。完整規則仍留在戰鬥紀錄與 forecast 文案，不把長說明塞進主要操作區。

### Build 多樣性

提示依 move 的真實交戰類型與當下 formationRow 計算，不依職業名稱。跨職拿弓、近戰游俠、戰鬥教士等仍使用同一規則，不會被 UI 暗示成非法玩法。

### 魔法可讀性

秘法／神術名稱必須保持既有學派與 Mana/Favor 資源標籤。M50 不允許把 `火球〔秘法 2〕` 再疊成 `火球〔秘法 2〕〔遠程〕`，避免玩家誤以為施法也受弓弩射界規則。

### 戰況變化

同一角色在後排與前排時，同一 mundane move 的 live label 必須同步改變。這是用來防止 M49 前線崩潰後 UI 還停留在開戰前提示的回歸門檻。

### 重入與狀態污染

同一 runtime member 被再次初始化戰鬥時，M50 suffix 不得疊加。魔法名稱、move id 與既有資源規則不得被改壞。

## 已知仍待後續處理的風險

- 城鎮 roster 的戰技清單目前仍讀靜態職業資料，因此基礎 guard 的舊名稱可能仍出現在「戰鬥外」的配置畫面；M50 優先處理真正決策發生的 live battle UI。
- 出發整裝的前／後排 tooltip 目前主要解釋受擊優先順序，尚未把 M49 的近戰／遠程命中規則直接寫入出發前規劃文案。
- 核心攔截 log 的既有「持盾上前」文字仍需要在後續做全域敘事清理；不能因 UI 已改名就假裝所有盾牌語意都消失。
- 角色戰鬥等級目前 Lv5 封頂，而無盡商路與公司層玩法會繼續延伸；這是長期戰鬥成長可能產生平台期的下一個系統級審查重點。

## 驗收

M50 gate 包含：

- 純 forecast 規則測試；
- live `startCombat()` 動態名稱整合測試；
- 玩家資訊公平性／標籤密度／魔法污染／守勢語意的 adversarial review；
- production build；
- M49 全套；
- core combat 與 M40–M48 regression。
