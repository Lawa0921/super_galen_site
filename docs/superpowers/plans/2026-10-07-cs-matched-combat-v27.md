# V27 原骨架持槍場景

> 執行：主代理唯一寫入，子代理唯讀檢核；沿用已授權的持續改善範圍，不提交或部署。

**目標：** 將原生 53 骨架、原身體與服裝、CC0 M4A1 放在同一可編輯場景，完成腰射、ADS、換彈接近彈匣三個姿勢，取得第一人稱及外部接觸證據。

**架構：** 保留來源 rest、網格、UV、權重和服裝 modifier；在 Blender Z-up 的原尺寸人體上用確定性的雙節 FK 與掌面座標設定姿勢。槍還原到來源公尺尺度，軀幹採側身站姿，手腕目標隨槍剛體轉換。手指屈曲使用原骨頭的局部軸，不能直接套用另一個 50 骨架的 Euler 角。

**Spec：** `docs/superpowers/specs/2026-10-03-browser-cs-design.md`

**範圍：** 原生作者場景候選；三張 key pose 不等同連續動畫。原服裝帶品牌及既有袖口問題，未通過不匯出 GLB、不放入 runtime。禁止隱藏新皮膚區域、重啟 V18–23 袖子試參數、改系統 GPU 設定。

## 驗收與步驟

- [x] 純數學 adapter 先 RED 再 GREEN：驗證槍座標正手性、來源比例、左右手掌方向、屈指方向與非法輸入。
- [x] 建立來源 hash 固定、三個姿勢可切換的 `.blend`；原 source 不覆写。關節連續、骨長不變、網格/UV/權重/rest 不變。
- [x] 背景 CPU 渲染三個 FPS 鏡位及左右袖口/握把外部近景；檢查實際接觸、穿模與視角，不用接觸點或 BVH 數字代替美術判斷。
- [x] 唯讀獨立審查。若穿模或握姿不合格，明列失敗位置，保留原生場景作為下一步作者入口，不宣稱已改善正式遊戲。
- [x] 所有 Python 工具測試、factory 驗证、可開啟 preview 與截圖。確認 runtime hash 未變。本輪不改瀏覽器邏輯，不重跑沒有新假設的效能 trace。

## 主要風險

1. 左右手語意與 Z-up/Y-up 轉換鏡射：固定點 fixture + 正 determinant。
2. 體態看似可達但關節分離：實際 Blender pose heads/tails + bone length。
3. 手指不同 rest 軸導致反折：左右手屈曲 fixture + 外部近景。
4. 原服裝 cuff 穿插：保留原 mask 狀態、雙側近景、不可因藏皮膚通過。
5. 三個姿勢誤稱完整換彈：preview 與報告明標「換彈姿勢，非動畫」。
