# 《星燈迷宮》Starlantern：DRPG 切片設計

日期：2026-10-14
狀態：待使用者審閱
取代：`lantern-hollow` 2D 橫向卷軸原型（實作第一步會整個刪除）

## 1. 目標與範圍

做一個能玩的短篇切片，風格參考《世界樹迷宮》：組隊探索迷宮，再進行回合制戰鬥。一輪流程 30–60 分鐘。第一版先求簡單、能玩，進階系統之後再加。

**成功標準**
- 從城鎮編隊開始，一路打到第 3 層頭目，全程沒有卡死或破圖，可以通關。
- 隊伍組成和站位的選擇，會實際影響打法。
- 美術全部是 codex 生成的靜態圖，風格一致，並經使用者核准。
- `npx vitest run` 全部通過，e2e 主流程通過。

**不在第一版範圍**
- 技能流派、技能樹與配點：之後依試玩自然衍生。
- 連攜技、頭腕腳三種封鎖、混亂、麻痺。
- 敵人前後排。
- FOE（地圖上看得見的強敵）。
- 多語系：第一版只做繁體中文。
- 加入 `/games` 大廳：使用者看過之後再加。

## 2. 遊戲循環

### 城鎮（選單介面，不走動）
- **公會**：招募角色、編隊（5 人：前排 3、後排 2）。
- **商店**：賣素材換錢；賣出的素材會解鎖新裝備，可以購買。
- **旅館**：付錢回滿 HP、TP，同時存檔。整個遊戲只有這裡能存檔。
- **出發**：從第 1 層開始，或從已到達樓層的樓梯處開始。

### 迷宮（俯視網格地圖）
- 隊伍以 1 個圖示在網格上一格一格移動，可以用鍵盤或觸控操作。
- 迷霧：走過的格子和周圍 1 格才會顯示，地圖會保留已探索的範圍。
- 隨機遇敵：每走一步累積遇敵值。畫面角落的指示燈依遇敵值顯示綠、黃、紅。
- 格子種類：牆、地板、門、上樓、下樓、寶箱、回城點（每層入口）、頭目房。
- 用道具「歸還之燈」可以隨時回城。
- 3 層，每層一種地形：林間遺跡、水晶洞窟、星燈神殿。第 3 層最深處是頭目「燈喰之獸」。

## 3. 世界觀與角色

邊境小鎮「露米亞」的地底，在一場地震後裂開一座古老迷宮。據說最深處沉睡著墜落的「星燈」，能讓長年籠罩小鎮的暮霧散去。8 位少女加入冒險者公會，組隊深入迷宮。每層會揭露一點真相，第 3 層頭目守護著星燈。

可招募 8 位角色，出戰 5 位。待在公會的隊員拿一半經驗值。每人有一組符合定位的技能（約 3–4 個），升到指定等級自動習得。第一版不分流派、不配點；流派之後依試玩自然衍生。

| 角色 | 建議站位 | 定位與技能方向 |
|---|---|---|
| 見習魔女 諾艾兒 | 後排 | 火、冰、雷攻擊；降低敵人能力、毒 |
| 巫女槍兵 千鶴 | 前排 | 全體攻擊；我方減傷 |
| 尋寶獵人 莉茲 | 前或後 | 多段攻擊；降低遇敵、素材掉落加成 |
| 森林遊俠 希爾薇 | 後排 | 單體高傷；先制攻擊、提高逃跑率 |
| 火焰騎士 絲嘉蕾 | 前排 | 吸引攻擊、替隊友擋傷；消耗 HP 打火屬性大傷害 |
| 月之法師 瑟蕾 | 後排 | 治療、復活、解毒；催眠 |
| 沙漠舞劍士 莎菲拉 | 前排 | 多段攻擊、提高閃避；全隊增益 |
| 技師 波比 | 後排 | 放置砲台每回合攻擊；道具效果加倍、護盾 |

隊伍設計原則：
- 只有瑟蕾是專職治療。
- 莎菲拉、波比、千鶴各有保命手段，所以沒有瑟蕾也能組出可行的隊伍。
- 適合前排的只有 4 人，組隊時要做取捨。

## 4. 戰鬥系統

- **回合流程**：每回合開始，先替 5 位隊員各選行動：攻擊、技能、防禦、道具、逃跑。之後所有角色依「速度 ± 亂數」排序，敵我穿插執行。
- **站位**：後排的近戰攻擊傷害減半，弓和法術不受影響。敵人的近戰攻擊打後排時傷害減半。敵人不分前後排。
- **資源**：HP 與 TP，技能消耗 TP。迷宮裡不會自然回復 TP。
- **屬性**：物理、火、冰、雷四種。每個敵人有弱點（1.5 倍傷害）和抗性（0.5 倍傷害）。用某屬性打過一次之後，那個屬性的倍率就會顯示出來。
- **狀態**：
  - 毒：每回合扣最大 HP 的固定比例。
  - 睡眠：無法行動，受到攻擊就醒來。
  - 增益、減益：每人最多 3 個，各有持續回合數。
- **防禦**：當回合受到的傷害減半。
- **逃跑**：成功率依速度差決定，頭目戰不能逃。
- **絕技量表**（2026-10-15 使用者追加）：每位隊員有 0–100 的量表，每次行動 +12，受到傷害時加「傷害 ÷ 最大 HP × 40」。量表滿了，戰鬥指令出現「絕技」；施放後歸零。量表跨戰鬥保留並存檔。每人一招專屬絕技，不耗 TP：諾艾兒「流星燈火」（火屬性全體）、千鶴「千鳥神樂」（物理全體）、莉茲「寶光亂舞」（單體 5 段）、希爾薇「星穿一矢」（單體超高傷害）、絲嘉蕾「紅蓮劫火」（火屬性全體）、瑟蕾「滿月之祈」（全隊大回復並解毒）、莎菲拉「沙漠蜃樓」（全隊攻擊與速度提升）、波比「全彈發射」（全體 2 段）。
- **絕技演出**：畫面暗下、斜向光帶滑入，帶上是角色的絕技頭貼放大版、集中線與絕技名稱，閃白後接特效，約 1.2 秒，並有專屬合成音效。全部由程式產生。
- **成長**：存活的出戰隊員拿全額經驗，待在公會的拿一半。升級提升能力值，到指定等級自動習得技能。
- **倒下與全滅**：倒下的隊員可以在旅館付錢復活，或用道具復活。全滅時讀取上次旅館的存檔。
- **戰鬥畫面**：
  - 該層的背景圖上方排列敵人大圖，下方是隊伍頭貼欄。
  - 所有動態都由程式產生：受擊閃白加震動、傷害數字、輪到誰時頭貼亮起並換成攻擊頭貼、被打中時短暫換成受擊頭貼、HP 30% 以下換成瀕死頭貼、倒下換成倒地頭貼、敵人死亡時碎裂淡出，再疊上單張特效圖。
  - 不使用逐幀動畫。

**內容量**
- 8 種一般敵人，每層 2–3 種，加 1 隻頭目。
- 約 15 件裝備：武器、防具、飾品各一個欄位。
- 約 10 種素材。
- 消耗道具：回復藥、TP 藥、解毒、復活、歸還之燈。

## 5. 美術

全部用 codex 生成靜態圖（`codex_still.py`，背景用 magenta 去背），不使用 PixelLab。

| 項目 | 數量 | 說明 |
|---|---|---|
| 角色立繪 | 8 | 全身、像素風。以 `runs/pixellab/lineup1`、`lineup2` 的造型為準，服裝收斂成一般冒險服 |
| 角色頭貼 | 48 | 每人 6 張：一般、攻擊、受擊、瀕死、倒地、絕技（2026-10-15 使用者追加，原為 2 張）。某張缺圖時退回一般頭貼；沒有倒地圖時把一般頭貼轉灰階 |
| 地圖隊伍圖示 | 4 | 上下左右，靜態；移動時用程式做滑動和彈跳 |
| 地形圖塊表 | 3 | 每層一張，固定網格：牆、地板、門、樓梯、寶箱。要拼接 QA |
| 戰鬥背景 | 3 | 每層一張 |
| 敵人 | 9 | 8 種一般敵人加 1 隻頭目，靜態大圖 |
| 圖示表 | 2–3 張 | 技能、道具、裝備、素材，以格子排列後切開 |
| 特效 | 約 8 | 斬擊、刺、打擊、火、冰、雷、回復、增益，單張圖 |
| 介面框 | 1 組 | 九宮格切片 |

**流程**：asset contract → codex 生成原圖 → 程式切圖、去背 → 機械 QA（去背殘留、半透明、尺寸、拼接）→ 使用者核准 → 發布到 `public/assets/games/starlantern/`。

**管理**：
- 原圖和紀錄放在 `art-factory/starlantern/`。
- 被退件的素材不能留在 runtime 路徑。
- 舊的 `art-factory/lantern-hollow/` 只把 8 人並排圖和騎士素材搬到新資料夾，其餘刪除。

## 6. 程式架構

- **頁面**：`src/pages/games/starlantern.astro`，第一版加 `noindex`。
- **程式**：`src/scripts/games/starlantern/`，結構與其他遊戲相同。
  - `data/`：純資料表，包括角色、技能、敵人、裝備、素材、道具、地圖格子、文字。
  - `engine/`：純邏輯，不碰 DOM。
    - `map.ts`：移動、碰撞、迷霧、格子事件。
    - `encounter.ts`：遇敵值與指示燈等級。
    - `battle.ts`：行動排序、傷害公式、屬性、狀態、增益減益、逃跑、勝敗判定。
    - `skills.ts`：技能效果執行。
    - `party.ts`：編隊、經驗、升級、依等級習得技能。
    - `town.ts`：商店、素材解鎖、旅館。
    - `save.ts`：存檔序列化，含版本號。
  - 隨機性：`engine` 的亂數一律由外部注入，測試可以固定種子。
  - `render/`：PixiJS 繪製地圖和戰鬥畫面。城鎮選單和戰鬥指令用 DOM。
  - `input/keymap.ts`：方向鍵、WASD、確認、取消，加上觸控按鈕。
  - `audio/SoundManager.ts`：Web Audio 合成音效，遵循 `__arcadeAudio` 的音量設定，並加進 `audio-sfx-volume.test.ts`。
- **樣式**：`src/styles/_starlantern.scss`。禁用 `!important` 和行內樣式。
- **存檔**：localStorage 鍵 `starlantern-save`。讀檔時版本不符或資料損毀，就提示並開新檔，不會讓遊戲崩潰。
- **文字**：第一版集中在 `data/text.zh-TW.ts`，之後要加多語系再接站內 i18n 雙檔制。
- **刪除舊原型**：
  - `src/pages/games/lantern-hollow.astro`
  - `src/scripts/games/lantern-hollow/`
  - `src/styles/_lantern-hollow.scss`
  - `tests/e2e/lantern-hollow.spec.ts`
  - `docs/lantern-hollow-poc.md` 與相關的 specs、plans
  - `art-factory/lantern-hollow/`（第 5 節列的保留項目除外）

## 7. 錯誤處理

- 存檔讀取失敗：提示「存檔無法讀取，已開始新遊戲」，同時保留壞檔的備份鍵。
- 素材載入失敗：顯示簡單的替代色塊並記錄到 console，遊戲仍然可以操作。
- 戰鬥中不可能出現的狀態（例如沒有存活的目標）：重新選擇目標。如果敵人全部死亡，直接結算。

## 8. 測試

- **Vitest，以 TDD 撰寫**，對象是 `engine/` 每個模組：
  - 移動與碰撞、迷霧揭露、遇敵值。
  - 行動排序、傷害公式與屬性倍率、後排減半、毒與睡眠、增益上限 3 個、逃跑、勝敗。
  - 經驗分配（含待在公會的一半）、升級、依等級習得技能。
  - 商店素材解鎖、旅館回復與存檔、存檔版本不符的處理。
  - 每個模組至少包含一個邊界或回歸案例。
- **資料完整性測試**：每個技能、敵人、裝備引用的 id 都必須存在；地圖必須可以從入口走到樓梯和頭目房。
- **Playwright e2e**（`tests/e2e/starlantern.spec.ts`，chromium）：進城鎮 → 編隊 → 進迷宮走幾步 → 觸發一場戰鬥並獲勝 → 回城住旅館存檔 → 重新載入，確認存檔還在。用測試用的種子固定遇敵。
- 測試瀏覽器一律 headless，加 `--mute-audio`。

## 9. 交付順序（實作計畫會細分）

1. 刪除舊原型。
2. 寫 `engine` 和 `data`（TDD），用測試迷宮驗證。
3. 用替代色塊做出可以操作的介面：城鎮選單、地圖、戰鬥。
4. 做美術：先做 1 位角色、1 種敵人、1 層圖塊，給使用者核准風格，之後再量產。
5. 換上正式美術，做數值平衡，跑 e2e，交給使用者試玩。
