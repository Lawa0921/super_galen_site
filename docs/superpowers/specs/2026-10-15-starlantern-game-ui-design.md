# 《星燈迷宮》遊戲介面改版設計

日期：2026-10-15
狀態：待使用者審閱
前提：`2026-10-14-starlantern-drpg-design.md`（遊戲本體）。本文件只改「畫面與操作」這一層；引擎、資料、存檔、平衡與已發布的 166 張美術沿用。

## 1. 目標

使用者的意見：介面太陽春，要「當成一個遊戲來做介面，不是一般的網頁」，並參考《世界樹迷宮》。

**成功標準**
- 整個遊戲是一塊固定比例的遊戲畫面，看不到任何網頁元素：沒有網站頁首、捲軸、網頁按鈕、下拉選單或分頁。
- 從標題畫面一路玩到通關，只用鍵盤就能完成；滑鼠和觸控也能完成。
- 每個畫面都有插畫或場景、遊戲視窗、游標和音效回饋，版面遵循《世界樹迷宮》的慣例。
- 新增美術全部由 codex 生成，經使用者核准；不抄《世界樹迷宮》的圖、字型或框線紋飾。
- `npx vitest run` 全部通過；e2e 以鍵盤走完主流程。

**不在這次範圍**
- 第一人稱 3D 迷宮視角：維持俯視網格地圖。
- 背景音樂、酒場委託、任務系統。
- 多語系：文字仍集中在 `data/text.zh-TW.ts`，且不烘焙進圖片（固定的遊戲標題 logo 除外）。

## 2. 畫面規格

- **邏輯解析度 640×360（16:9）**。所有畫面元素都用這個座標系排版。
- **縮放**：放大倍數取 `floor(min(視窗寬 ÷ 640, 視窗高 ÷ 360))`，最少 1 倍，維持像素銳利。視窗比 640×360 還小時（手機直向），改用小於 1 的等比例縮放。多出來的部分補黑邊並置中。
- **全螢幕**：設定裡可以切換，F11 也可以。
- **網頁本身**：只剩黑底和一塊遊戲畫面。頁面不會捲動，沒有網站頁首或頁尾。保留 `noindex`。
- **字型**：使用「俐方體 11 號」（Cubic 11，SIL Open Font License 1.1）。字型檔放在站內 `public/assets/fonts/`，旁邊附上 OFL 授權檔。內文用 12 px，行高 16 px。
- **實作分層**（推薦的做法）：
  - 一個固定 640×360 的容器，用 CSS `transform: scale()` 整體放大。
  - 底層是 PixiJS 畫布，負責地圖與戰鬥場景。
  - 上層是 DOM 做的遊戲視窗、選單與文字。
  - 選這個做法的理由：DOM 文字清楚、能做無障礙、沿用 happy-dom 單元測試；全部改用 Pixi 的話，文字和測試成本都高很多。
  - 視窗一律絕對定位在 640×360 座標內；禁用 `!important` 和行內樣式的規則照舊，所以位置寫在 SCSS 的 class 裡。

## 3. 操作

| 動作 | 鍵盤 | 滑鼠／觸控 |
|---|---|---|
| 移動游標或在地圖上行走 | 方向鍵、WASD | 指到選項就移動游標；地圖上用畫面內的十字鍵 |
| 確認 | Z、Enter、空白鍵 | 點選項 |
| 取消／返回 | X、Esc、Backspace | 右鍵，或畫面上的「返回」小按鈕 |
| 迷宮中開啟選單 | C、Esc | 畫面上的「選單」小按鈕 |
| 戰鬥中全員攻擊 | A | 指令視窗裡的「全員攻擊」 |
| 全螢幕 | F11 | 設定畫面 |

- 選單是一層一層疊起來的。取消會回到上一層，最上層的取消等於「離開」。
- 游標會跳過不能選的項目，到頭會繞回另一端。
- 游標移動、確認、取消、錯誤（例如錢不夠）各有一種合成音效，音量依照全站的 `__arcadeAudio` 設定。

## 4. 共用介面元件

- **視窗**：深色半透明底、九宮格邊框，四角有星燈紋飾，邊框圖由 codex 生成。視窗出現時有約 0.12 秒的展開動畫。
- **游標**：選中的那行有一條亮色光帶，左側是會微微擺動的箭頭游標；箭頭圖由 codex 生成。
- **對話框**：畫面下方，左上角有名牌。文字逐字打出，按確認鍵可以直接顯示全部，再按一次關閉。
- **確認框**：「要花 120 G 住宿嗎？是／否」這類詢問。
- **數值條**：HP、TP、絕技量表，數值變化時有動畫。
- **場景切換**：淡出、淡入，約 0.3 秒。
- **提示訊息**：例如「存檔無法讀取，已開始新遊戲」，一律用對話框顯示，按確認關閉。

## 5. 各畫面

1. **標題畫面**：標題插畫和遊戲 logo，選單有「新遊戲／繼續／設定」。
   - 沒有存檔時，「繼續」不能選。
   - 已有存檔時選「新遊戲」，會先確認是否覆蓋。
2. **城鎮**：露米亞全景插畫。
   - 左上是地名牌，右上是金錢。
   - 左邊是設施選單：冒險者公會、道具店、旅館、迷宮入口、設定。
   - 下方對話框從一組台詞裡隨機挑一句，依進度變化。
3. **冒險者公會**：公會場景插畫，右側是櫃台小姐，左邊是指令「編隊、招募、裝備、狀態、離開」。
   - **編隊**：前排 3 格、後排 2 格的站位板，每格顯示頭貼與名字。選一格再選一位隊員就交換，也可以把格子清空。
   - **招募**：列出還沒招募的角色，選中時顯示立繪、定位說明和初始能力。
   - **裝備**：選隊員，再選武器、防具或飾品欄，再選裝備；清單上標出能力增減。
   - **狀態**：一位隊員的立繪、能力值、已學與將學的技能（含習得等級）、絕技說明與量表。
4. **道具店**：店內插畫，右側是店主，左邊是指令「購買、販賣、離開」。
   - **購買**：清單每行是圖示、名稱、價格、持有數；尚未解鎖的商品顯示所需素材。右邊的說明欄顯示效果，裝備則列出每位隊員能不能裝、能力增減。購買時用左右鍵調數量。
   - **販賣**：素材清單，用左右鍵調數量後確認；賣出後解鎖新商品時，店主會說話。
5. **旅館**：大廳插畫，右側是老闆娘，左邊是指令「休息（價格）、復活、離開」。
   - **休息**：確認後淡出，顯示「隔天早上」，淡入後提示「已存檔」。
   - **復活**：列出倒下的隊員和價格。
6. **迷宮入口**：裂口外的營地插畫，右側是守門老兵。用樓層卡片選要去哪一層：卡片是該層戰鬥背景的縮圖加樓層名，還沒到過的顯示上鎖。
7. **迷宮**：
   - 上方 296 px 高是地圖，下方 64 px 是隊伍狀態列：5 格，每格有依狀態變化的頭貼、名字、HP／TP 條、絕技量表。
   - 左上是樓層名，右上是遇敵指示燈（綠、黃、紅）。
   - 寶箱、樓梯、回城點、頭目房的事件，都用對話框顯示並等玩家確認。
   - **迷宮選單**：隊伍狀態、道具（迷宮裡可以用回復類道具）、歸還之燈、設定、關閉。
   - 觸控時，畫面右下角顯示十字鍵。
8. **戰鬥**：
   - 背景、敵人、特效、碎裂沿用現有畫面。
   - 上方訊息列依序播放行動訊息，例如「絲嘉蕾的攻擊！」「苔蘚史萊姆受到 12 點傷害」，取代現在的整段紀錄。
   - 下方是 5 格隊伍狀態，輪到誰時那格會亮起。
   - 指令視窗在左下：攻擊、技能、防禦、道具、絕技（量表滿時才出現）、逃跑。
   - 技能和道具的子視窗會列出 TP 和說明。
   - 選目標：選敵人時，箭頭游標出現在敵人頭上；選隊友時，該隊友的狀態格亮起。
   - 結算視窗：經驗、金錢、掉落、升級、新學會的技能，按確認關閉。
9. **全滅**：「全滅……」畫面，確認後回到上次在旅館存檔時的狀態。
10. **通關**：結局插畫，可以使用頭目的戰鬥背景，配上感謝遊玩的文字，以及「回到標題」。
11. **設定**：音效音量、文字速度（慢、中、快、立即）、全螢幕、按鍵說明。設定存在 localStorage 鍵 `starlantern-settings`，讀取失敗時用預設值。

## 7. 程式架構

- `src/pages/games/starlantern.astro`：只放遊戲畫面的容器，`#sl-screen` 裡有 `#sl-canvas` 和 `#sl-ui`。
- 新增 `src/scripts/games/starlantern/ui/` 下的模組，以下都是純邏輯或 DOM 元件，各自有測試：
  - `screen.ts`：縮放計算與全螢幕。
  - `menu.ts`：選單模型，包括游標、跳過不能選的項目、繞回、層層疊起的選單。
  - `input.ts`：把鍵盤、滑鼠、觸控轉成「移動／確認／取消／選單」動作，交給目前在最上層的選單。
  - `scenes/`：每個畫面一個檔案（`title`、`town`、`guild`、`shop`、`inn`、`gate`、`dungeon`、`battle`、`result`、`gameover`、`clear`、`settings`），共用 `Scene` 介面：`enter()`、`exit()`、`onAction()`。
  - `widgets/`：視窗、對話框、確認框、數值條、狀態列。
  - `settings.ts`：讀寫設定。
- 舊的 `ui/town.ts`、`ui/hud.ts`、`ui/battleMenu.ts`、`ui/clear.ts` 由新的 scene 取代並刪除。`ui/art.ts`、`ui/cutin.ts` 沿用。
- 引擎只新增一項：迷宮裡使用回復類道具 `useFieldItem(state, itemId, targetId)`，用 TDD 補上。
- `client.ts` 改成建立畫面、scene 路由與輸入系統。
- 樣式：`_starlantern.scss` 改寫，選擇器都放在 `.sl-screen` 底下。

## 8. 錯誤處理

- 字型或美術載入失敗：退回系統字型，或沿用現有的色塊，遊戲照常可以操作，並記錄到 console。
- 設定或存檔損毀：用對話框提示後改用預設值或開新檔，沿用現有存檔的處理。
- 視窗太小：照樣等比例縮小，不會出現捲軸。

## 9. 測試

- **Vitest**：選單模型（游標、跳過、繞回、疊層、取消）、輸入對應、縮放計算、設定讀寫，以及每個 scene 的 DOM 輸出與操作（例如公會換位、商店調數量、旅館確認流程）。
- **引擎**：`useFieldItem` 的成功、失敗與邊界案例。
- **Playwright e2e**（chromium、headless、`--mute-audio`）：只用鍵盤，從標題 → 新遊戲 → 公會看編隊 → 迷宮入口 → 進迷宮走到遇敵 → 戰鬥勝利 → 結算 → 歸還之燈回城 → 旅館休息存檔 → 重新載入 → 繼續，確認存檔還在。另外驗證壞掉的存檔、畫面上沒有捲軸，以及頁面上沒有原生的 button、select 元素在畫面外露出。

## 10. 交付順序

1. 字型、畫面容器與縮放、選單和輸入系統、視窗元件（先用 CSS 暫代邊框），做出可以操作的標題畫面和城鎮選單。
2. 7 張美術樣張，給使用者核准風格。
3. 公會、道具店、旅館、迷宮入口。
4. 迷宮畫面與迷宮選單；戰鬥畫面與結算。
5. 剩下 10 張美術，給使用者核准後發布。
6. 全滅、通關、設定；e2e 重寫；整體審查；給使用者試玩。
