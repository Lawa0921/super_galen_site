# 星燈迷宮：每次潛入都不同的迷宮（roguelike 探索）設計

日期：2026-10-16
狀態：草案，已納入使用者對無限深度與全滅懲罰的決定，待使用者核准

## 1. 為什麼要做

使用者原話：「我想把地城做成一個像是 rogue like 的探索，每一次進去都有不一樣的狀況，這樣感覺比較有趣。」

目前三層樓的地圖是固定的。寶箱開過一次就空了，走過一次就記得路，第二次進去沒有新鮮感，只剩重複的戰鬥。

這次的目標，是讓每次從城鎮出發都是一趟新的冒險：地形不同、遇到的事件不同、寶物不同，還要有冒險當下才要做的取捨。

## 2. 目標、非目標、反目標

**目標**
- 每次「出發」都產生一份新的迷宮：每層的地形、寶箱、事件、樓梯位置都不同。
- 迷宮裡有比戰鬥更多的事可做：隨機事件房、寶箱、陷阱、商人、泉水、精英怪。
- 每趟潛入有一個「本次狀況」，例如濃霧、豐收、兇暴，讓每趟的打法不同。
- 角色成長保留下來，保持「越打越強、越走越深」的長期動機。這是 roguelite，不是死了就從頭來過的硬派 roguelike。
- 相同的亂數種子產生相同的迷宮，方便測試、重現問題，以及之後做「每日迷宮」。

**非目標**
- 這次不做硬派 roguelike 的永久死亡或刪除存檔。
- 不新增樓層主題或怪物種類。沿用現有 3 層的主題、敵人和地磚，只是重新排列；更深的樓層循環使用這 3 種主題（見 §3.7）。
- 不改戰鬥系統本身。

**反目標**（技術上能動，但等於失敗）
- 產生的迷宮走不通，例如樓梯或出口被牆封住、寶箱在牆裡。
- 地圖看起來像隨機雜訊，沒有「房間和走廊」的結構感。
- 隨機性大到讓玩家覺得努力沒有用，例如開局連續被精英怪堵死。
- 頭目樓層隨機到無法挑戰。

## 3. 這次決定的規則

以下是我的判斷；使用者可以在核准時改。

### 3.1 一趟潛入（run）
- 從城鎮「迷宮入口」出發時，產生一個新的潛入種子。這趟的每一層都由這個種子決定。
- 回到城鎮時（走回入口、歸還之燈、全滅），這趟就結束。下次出發會換成新的迷宮。
- **全滅（使用者決定）**：經驗與等級保留；這趟撿到、還沒帶回城的裝備和素材全部失去；身上的金幣扣 25%。不再讀回旅館存檔。
  - 這趟的戰利品先放在「冒險背包」，平安回城時才併入倉庫。
  - 存檔仍然只在旅館進行，所以全滅後若沒有住宿就關掉遊戲，讀檔時會回到上次住宿的狀態。
- 捷徑保留：已經抵達過的最深樓層，還是可以從入口直接出發。這次是「從第 N 層開始的新潛入」，地形照樣重新產生。
- 存檔只在旅館進行，這點不變。存檔會記錄「目前沒有進行中的潛入」，所以讀檔後一定是在城鎮。

### 3.2 地圖產生
- 每層的大小落在 21×15 到 27×19 之間，越深越大。
- 演算法：在網格上放 6 到 10 個不重疊的矩形房間，用最小生成樹把它們連起來，再隨機多加 1 到 2 條通道形成迴路，以 L 形走廊連接。走廊的寬度是 1 格。
- 入口房和樓梯房要相隔夠遠：在房間圖上取彼此最遠的兩個房間。
- 第 3 層（頭目層）的最遠房間是頭目房，房門前一格放門。
- 產生完一定要驗證：入口到樓梯（或頭目）可以走到；每個寶箱和事件都可以走到。驗證失敗就用下一個種子重來，最多 20 次，之後退回固定地圖。
- 輸出沿用現有的 `FloorMap` 格式。這樣地圖繪製、霧、牆壁自動拼接都不必改。

### 3.3 房間內容
每個非入口房會被指定一種內容，比例依樓層調整：

| 內容 | 說明 |
|---|---|
| 空房 | 一般的遇敵機率 |
| 寶箱 | 1 到 2 個，內容從該層的寶箱表抽 |
| 泉水 | 回復全隊 HP 和 TP 的 30%，每趟只能用一次 |
| 陷阱 | 踩到時隨機二選一：全隊受傷或中毒；走過去之前看不到 |
| 流浪商人 | 用當層價格賣 3 樣隨機道具 |
| 祭壇 | 二選一的取捨，例如「獻上 20% HP 換本趟攻擊 +15%」，或「放棄」 |
| 精英怪 | 房中央有一隻看得見的強敵（一般怪強化版，標示★）；打倒必掉稀有素材 |
| 寶庫 | 上鎖的大寶箱，要先在同層撿到鑰匙 |

每層至少要有 1 個寶箱房；精英怪最多 1 隻；寶庫最多 1 間。

### 3.4 本次狀況
每趟潛入隨機抽 1 種，出發時用橫幅顯示，迷宮畫面角落也一直顯示。

| 狀況 | 效果 |
|---|---|
| 濃霧 | 視野範圍只有自己這一格，遇敵率 −20% |
| 豐收 | 寶箱多 1 個，素材掉落 +50% |
| 兇暴 | 敵人攻擊 +20%，經驗值 +30% |
| 靜謐 | 遇敵率 −40%，陷阱 +1 |
| 星落 | 每層必有 1 個精英怪，金幣 +50% |
| 平穩 | 沒有特殊效果 |

### 3.5 小地圖與可讀性
- 迷宮畫面右上角加一張小地圖，畫出已探索的房間、自己的位置，以及已發現的樓梯、寶箱和事件。
- 地圖上有內容的格子（寶箱、泉水、商人、祭壇、精英怪）會有閃爍的圖示標記，進到看得到的範圍就會出現；陷阱除外。

### 3.7 無限深度（使用者決定）
- 迷宮往下無限延伸。第 3 層之後還有第 4、5、6……層，地形主題依「林間遺跡 → 水晶洞窟 → 星燈神殿」循環。
- 敵人依深度變強，用「深度等級」取代敵人身上沒有的等級欄位：
  - 深度等級 = 2 + 4 ×（層數 − 1）；
  - 敵人的能力值依深度等級，乘上相對第 1 輪的倍率；
  - 經驗值與金幣也跟著提高。
- 遇敵表循環使用 3 種主題的敵人。從第 4 層開始，敵人名稱前加「深層」，例如「深層苔蘚史萊姆」。
- 每 5 層（第 5、10、15……層）是頭目層，頭目是「燈喰之獸」依深度強化的版本。第 3 層的劇情頭目維持原樣，打倒時觸發通關。
- 捷徑：入口可以從「已抵達的最深層」或「任一個 5 的倍數層」出發。
- 平衡要求：同深度等級的隊伍，在各層的勝率落在現有範圍內。

### 3.6 與現有系統的關係
- 遇敵：照舊用各層的遇敵表和遇敵量表，只是再乘上本次狀況的倍率。
- 寶箱：不再寫進 `dungeon.opened`。已開過的寶箱只記在這趟潛入裡。
- 已探索紀錄：只記在這趟潛入裡，回城後清空。
- 頭目：打倒後會記錄 `bossDefeated`，之後的第 3 層頭目房改放「再戰」的精英頭目，獎勵減少。
- 通關畫面：維持現狀，第一次打倒頭目時顯示。

## 4. 限制
- 產生地圖要在 50ms 內完成，因為一般手機也要流暢。
- 純函式：輸入（種子、樓層、本次狀況），輸出（地圖、房間內容）。不讀全域狀態，可以直接寫單元測試。
- 這次使用者已表示不用管舊存檔，所以存檔版本號直接加 1。
- 美術只用現有素材。事件圖示（泉水、商人、祭壇、陷阱、寶庫、鑰匙、精英怪標記）要走美術流程，經使用者核准；核准之前先用文字標記代替，例如「泉」「商」，不做假圖示。

## 5. 留給實作者決定的部分
- 房間大小的確切範圍、走廊彎折的位置。
- 各內容在每層的比例，只要符合 3.3 的最少與最多數量。
- 小地圖的外觀細節。
- 祭壇的具體選項內容。需要 3 到 5 種，數值要過平衡模擬。
- 精英怪的強化倍率，必須讓平衡模擬維持：同等級正常隊伍勝率 ≥ 60%。

## 6. 驗收
- 對 1000 個種子產生每一層，100% 都要通過可達性驗證，而且耗時都在限制內。
- 同一個種子產生相同的結果。
- 平衡模擬加入事件與狀況的期望值後，各層勝率仍落在現有範圍內。
- 實機截圖要涵蓋：每種房間內容、每種本次狀況的橫幅、小地圖。
- 端對端流程：出發 → 探索 → 下樓 → 回城 → 再出發，第二次的地圖必須和第一次不同。

## 7. 實作者檢查後的決定（我的判斷，標註供使用者核對）
- 先做本迷宮，寶箱、寶庫、精英怪暫時沿用現有的寶箱表與素材；養成系統上線後，改從掉落系統抽。
- 兩份設計各自把存檔版本號加 1，舊檔重置。
