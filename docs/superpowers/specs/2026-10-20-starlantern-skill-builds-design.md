## 2. 目標

1. **同一招，多種玩法**：可移動的「符文」改變一招**怎麼打**（目標、段數、屬性、附加異常、觸發、消耗），不是只加數字【控制者】。
2. **每個人不一樣**：每位角色有一個別人沒有、戰鬥畫面上看得到的核心機制；隊伍中重複的招式收斂到最適合的那一位【控制者】。
3. **技能樹的節點會改規則**：拿掉「+10%」型強化節點，換成會改變招式或機制的「變招」節點【控制者】。
4. **屬性有意義**：新增元素異常（灼燒、凍結、感電）與物理的流血，讓轉換屬性真的改變打法【控制者】。
5. **不用心算**：裝符文前，畫面直接顯示這招「之前 → 之後」的每一項數字【控制者】。
6. **懶人也能玩 build**：每位角色 2–3 套建議 build，一鍵套用【控制者】。
7. **普通難度不需要符文**：預設配點、不裝任何符文就能通關普通；現在凍結的平衡帶就是普通的平衡帶【使用者】【控制者】。

## 3. 非目標

- 不設計噩夢、地獄地城本身（只留 §13 的掛鉤）【控制者】。
- 不改天賦盤（24 格數值節點與關鍵天賦照舊）【設計裁定】：理由是天賦盤剛做完、和本次的痛點（招式無聊、角色同質）無關；改它會讓平衡重調的範圍加倍。
- 不改絕技（ultimate）；絕技不能裝符文【設計裁定】：理由是絕技量表的經濟和第 11、14 項平衡帶綁在一起，保持一招固定的高潮最好懂。
- 不新增角色、不改等級上限、不改技能點與天賦點的曲線（`progression.skillPoints`、`talentPoints`）【設計裁定】：理由是點數節奏會牽動每一條平衡帶。
- 洛恩的通才定位不收斂（§8.10）：他的招式和夥伴重疊是刻意的（`data/hero.ts` `HERO_PEAK_SHARE = 0.85`，故事 spec §4.5「任何隊伍組成都要可以用」，平衡第 18 項）。
- 不做線上交易、不做符文的隨機詞綴。

## 4. 反目標（就算做出來能動，這些情況也算失敗）

| 失敗樣態 | 為什麼是失敗 | 本文怎麼防 |
|---|---|---|
| **看不懂**：要心算倍率、要記隱藏規則、一個符文要兩句話才講得完 | 使用者明說會懶得研究 | 一個符文＝一句話（§6.4）；裝之前看「之前 → 之後」（§6.8）；不相容的符文直接變灰並寫出原因 |

## 6. 符文（輔助寶石）【控制者：方向】【設計裁定：細節】

### 6.1 流亡暗道的哪些做法被採用、怎麼簡化

| 流亡暗道（PoE）的做法 | 在本作的樣子 | 為了直覺做的簡化 |
|---|---|---|
| 輔助寶石＋標籤：輔助只能連到標籤相符的技能 | **符文**＋**標籤**：符文寫明它需要的標籤，不相符的在清單裡變灰並寫出原因 | 標籤由技能資料**自動推導**，不手寫（§6.2），所以不會標錯；標籤只有 15 個左右，每招顯示成小標籤 |
| 連結與插槽隨裝備成長 | 每招的符文槽：1 → 2 → 3，**跟角色等級自動開** | 不用打孔、不用連結石、不看裝備；所有技能同時開槽 |
| 寶石等級與品質 | 符文的**階級**（普通、魔法、稀有、史詩）決定數字；三個同名同階在鍛造屋**合成**升一階 | 沒有經驗值、沒有品質百分比；同名同階的符文永遠一樣，可以堆疊 |
| 變異（transfigured）寶石：同一招的另一個版本 | 技能樹的**變招節點**：同一招的兩個版本二選一 | 變招不是掉落物，是樹上的節點；二選一，可以免費換邊 |
| 關鍵天賦（keystone）改規則 | 已有的關鍵天賦照舊；新增**機制節點**改寫角色核心機制的規則（§7） | 機制節點只出現在該角色自己的樹上 |
| 元素轉換鏈（物理→雷→冰→火） | **屬性符文**：把一招的屬性整個換成火、冰或雷 | 不做部分轉換、不做轉換鏈；一招最多一個屬性符文。唯一的「輪轉」做成一個傳說符文 |
| 觸發（暴擊時施放、受擊時施放） | **觸發符文**：裝在「被觸發的那一招」上，寫明條件 | 不用另外指定要觸發誰；觸發出來的招不能再觸發；每個條件每回合每人最多一次 |
| 光環保留魔力上限 | **常駐符文**：增益技改成整場常駐，代價是保留 TP 上限 | 數字直接顯示「TP 上限 120 → 84」；保留總和最多 90% |
| 元素異常（點燃、冰緩／冰凍、感電）、流血 | 灼燒、凍結（頭目改冰緩）、感電、流血（§9） | 異常不會自動發生，只來自寫明的技能、符文、變招、敵人技能；每種一句話講完 |
| 傳奇物品改寫技能 | 現有的傳說威力照舊，等於「裝在裝備上的固定符文」，不佔符文槽 | 只把被刪掉的招的威力改指向新招（§10.1） |

### 6.2 標籤（自動推導）

標籤從技能「現在的樣子」推導：基礎招式 → 技能樹階級 → 變招 → 洛恩的武器精通 → 傳說威力，**不含符文**。

| 標籤 | 條件 |
|---|---|
| 傷害、治療、增益、減益、異常、裝置 | 有 `damage`／`heal`（或 `revive`）／對我方的 `buff`／對敵方的 `buff`（負值）／`inflict`／裝置效果 |
| 單體、全體、自身 | 目標是 `enemy`、`ally`、`deadAlly` → 單體；`enemies`、`allies` → 全體；`self` → 自身 |
| 多段 | 任一傷害效果 `hits ≥ 2` |
| 近戰、遠程 | 傷害效果的 `melee` |
| 武技、法術 | 傷害的 `scale` 是 `atk` → 武技；`mag` → 法術（流亡暗道的「攻擊／法術」） |
| 物理、火、冰、雷 | 傷害的 `element` |

【設計裁定】相容性只看「裝符文之前」的標籤。理由：如果先裝的符文會改變標籤，能不能裝就和順序有關，玩家會困惑（反目標「順序有關」）。
【設計裁定】例外：屬性符文會讓**異常符文**的屬性需求成立。例如物理的箭雨裝了「灼焰」變成火，就能再裝「點燃」。這是本系統最重要的「組合發現」，所以明寫成規則，畫面上「點燃」的說明寫「需要：火（可由屬性符文提供）」。這是唯一的例外。

### 6.3 資料模型

```ts
type RuneTier = 'common' | 'magic' | 'rare' | 'epic' | 'legendary';   // 沿用 data/gear.ts 的 Rarity 字串與顏色
interface RuneDef {
  id: string; name: string;            // zh-TW 名稱，例「擴散」
  group: 'shape' | 'hits' | 'element' | 'ailment' | 'trigger' | 'economy' | 'support' | 'legendary';
  needs: Tag[][];                      // 外層 OR、內層 AND，例 [['單體','傷害'], ['單體','治療']]
  text: (tier: RuneTier) => string;    // 一句話，含這一階的數字
  mod: (tier: RuneTier) => RuneMod;    // 純資料；RuneMod 是 SkillMod 的超集合
}
// 存檔
GameState.runes: Record<string, number>          // 鍵 `${id}@${tier}`，值是袋子裡（未鑲嵌）的數量
Member.sockets?: Record<string, (RuneRef | null)[]>   // 技能 id → 插槽；RuneRef = { id, tier }
```

- 【設計裁定】符文**沒有隨機數值**：同名同階永遠同一個數字，所以可以用計數堆疊，不需要 uid。理由：比較兩個符文不用看數值、存檔小、合成簡單；隨機性來自「掉到哪一種、哪一階」。
- 【設計裁定】鑲嵌中的符文從袋子扣掉；拆下回到袋子。符文袋不佔裝備背包的格子，每種最多疊 99。
- 傳說符文只有一階（`legendary`），不能合成。

| 觸發 | 受擊觸發 | 任何 | 她受到攻擊後，自動施放這招（威力 60%，不耗 TP）。 |
| 經濟 | 回氣 | 傷害 | 每段命中回復 1 TP；威力 85%。 |
| 經濟 | 節流 | 消耗 TP | TP −35%；威力與效果 80%。 |
| 經濟 | 蓄力 | 消耗 TP | TP +60%；威力與效果 140%。 |
| 經濟 | 吸血 | 傷害 | 造成傷害的 8% 回復自己的 HP。 |
| 輔助 | 延長 | 增益、減益或裝置 | 持續 +2 回合；TP +2。 |
| 輔助 | 共享 | 自身＋增益 | 改為對我方全體，效果 50%。 |
| 輔助 | 常駐 | 增益 | 戰鬥開始時自動生效且整場不消失，效果 60%；保留這名角色 30% 的 TP 上限。 |
| 輔助 | 淨化 | 治療或增益 | 額外解除目標的所有異常。 |
| 輔助 | 破甲 | 物理＋傷害 | 無視目標的護甲與格擋；TP +20%。 |
| 傳說 | 雙重詠唱 | 消耗 TP | 這招連續施放兩次；TP ×2。 |
| 傳說 | 星燈輪轉 | 傷害 | 每次施放，屬性依火 → 冰 → 雷輪替（這是唯一的「轉換鏈」）。 |
| 傳說 | 血之代價 | 消耗 TP | 不消耗 TP，改為消耗「TP×3%」的最大 HP。 |

約 27 種一般符文、6 種傳說符文。範例：瞄準射擊（單體物理遠程）＋擴散＋灼焰＋點燃 → 「對全體的火焰箭，會燒」；同一招＋蓄力＋暴擊觸發 → 「平常不太用，暴擊時自己飛出去的追擊」。這就是使用者確認的「同一招變成完全不同的玩法」。

### 6.5 插槽、取得、移動

- **插槽數**【設計裁定】：角色 Lv5 起每招 1 槽、Lv20 起 2 槽、Lv35 起 3 槽，所有主動技同時開。被動技（潛行、尋寶直覺、改造）沒有插槽。理由：控制者的「起初 1 槽、之後最多 3 槽」；跟等級自動開最不用管理。
- **取得**【設計裁定】：
  - 掉落：一般怪 3%、寶箱 10%、菁英 25%、頭目必掉 1 個（起始值，§12 調）。傳說符文只從菁英與頭目掉（傳說級機率沿用 `rarityWeights` 形狀，起始為菁英 2%、頭目 8%）。
  - 階級權重沿用裝備的 `rarityWeights(source, depthLv, cond)` 前四階（普通、魔法、稀有、史詩），越深越好。
  - 第一位頭目被擊倒**之後**才開始掉符文，那一場必掉一個魔法階「擴散」，並播一次教學。理由：讓第一次接觸發生在有空讀說明的時候，並保證每個存檔都有同一個起點。
  - 歐里克的道具店在第一個頭目之後固定賣 4 種普通階符文（擴散、連擊、節流、延長）。理由：保證每一套建議 build 至少能用普通階湊齊，噩夢的假設才站得住（§13）。
  - **決定性**：符文掉落用新的加鹽串流 `RUNE_SALT`（照 `STARLIT_SALT`、`chestHasGear` 的做法：`mulberry32(mix(seed ^ RUNE_SALT, key))`），既有的 `game.rng`、`lootRng` 等串流一次都不多抽，所有現有的重播與測試序列不變。
- **移動**【設計裁定】：戰鬥外（城鎮、迷宮的野外選單）隨時免費拆裝，永不損毀；符文可以從任何角色的任何技能移到任何角色。理由：鼓勵試 build；符文是全隊共用的戰利品。
- **合成**【設計裁定】：鍛造屋新增「符文合成」：三個同名同階 → 一個高一階，付金幣與一份精華（普通→魔法用 `essence-common`，依此類推，沿用現有精華）。重複的掉落因此有用，也是素材的出口。
- **賣出**：道具店收購，價格依階級。

### 6.6 疊加與衝突規則（寫一次，引擎只在一處套用）

1. **套用順序**（延伸 `engine/skills.ts` `patchSkill` 的註解）：基礎 → 樹的階級 → 變招 → 洛恩的武器精通 → 傳說威力 →〔在此計算標籤〕→ 符文 → 深淵加成（戰鬥中）→ 所有 `extra` 附加效果最後。
2. **同群組互斥**：形狀（擴散、集中、連鎖）、段數（連擊、重擊）、屬性、觸發，每群組一招最多一個。同一個符文不能在同一招裝兩個。其他群組可以並存。
3. **可交換的數學**：所有威力百分比**相乘**；TP 百分比**相加**後再乘（例：節流 −35% ＋ 蓄力 +60% ＝ +25%）；TP 固定值相加；持續回合相加；同一種異常的多個來源**取最高機率**，不相加；然後才套 `tpCost`，最低 1。結果和插槽順序無關（排列測試）。
4. **失效而不拆除**：換掉傳說裝備或退掉變招，使某個已鑲嵌的符文不再相容時，符文留在原位但變灰、標「未生效：需要『單體』」，不自動拆。理由：玩家換回裝備時 build 不會壞掉。
5. **觸發**：觸發出來的施放不耗 TP、不能再觸發任何東西、不會累積絕技量表；同一角色同一個觸發條件每回合最多一次；它用這招的其他符文（觸發符文本身除外）。
6. **常駐**：多個常駐符文的保留相加，最多 90%；在戰鬥開始時依隊伍順序生效；被保留的 TP 上限在戰鬥外也顯示在狀態頁。
7. 符文不影響：絕技、普通攻擊、道具、被動技。野外施放（`engine/field.ts`）照樣吃符文（因為它走 `skillFor`），但觸發、常駐只在戰鬥中。

### 6.7 代價模型與階級數字【起始提案】

- 原則：符文在**對的 build 裡**是升級（大約等於 +15%～30% 有效輸出，魔法階），在不對的地方是側移或降級。代價主要是 TP（流亡暗道的魔力倍率），改變形狀的符文用威力付代價。
- 階級只改「好處」那個數字，代價不變（玩家只要記一件事：階級越高越好用）：

| 符文 | 普通 | 魔法 | 稀有 | 史詩 |
|---|---|---|---|---|
| 擴散（威力） | 55% | 60% | 65% | 70% |
| 集中（威力） | 160% | 170% | 180% | 190% |
| 連擊（每段） | 70% | 75% | 80% | 85% |
| 點燃、感電、撕裂（機率） | 30% | 35% | 40% | 45% |
| 回氣（每段 TP） | 1（威力 80%） | 1（85%） | 1（90%） | 2（90%） |
| 蓄力（威力，TP 固定 +60%） | 130% | 140% | 150% | 160% |
| 常駐（效果，保留固定 30%） | 50% | 60% | 70% | 80% |

其他符文照這個模式由實作者填，寫成一張表放在 `data/runes.ts`。

## 7. 技能樹改版：變招節點與機制節點【控制者：方向】【設計裁定：細節】

- 55 個強化節點全部換掉。每條分支仍是 5 層（`TIER_GATE`、`skillPoints`、`DEFAULT_CAPSTONE` 的結構不變），強化節點的位置換成兩種新節點：
  - **變招節點**：同一招的兩個版本二選一，例：「火之星彈・連星（2 段，每段 60%）」或「火之星彈・重星（熱度 +2，威力 130%）」。
  - **機制節點**：改寫角色核心機制的規則，例：諾艾兒「冷靜」（熱度上限 5 → 7）。每位夥伴 1–2 個。
- 【設計裁定】變招與機制節點**保留 3 階**：第 1 階給規則改變，第 2、3 階只加深這條規則自己的數字（例：連星每段 60% → 65% → 70%），不再是「威力 +10%」。理由：每棵樹的點數容量維持現狀（夥伴約 37 點對 Lv50 的 26 點，約七成，符合養成 spec §6「必須取捨」），預設配點的節奏和平衡帶不被牽動。
- 【設計裁定】二選一的版本做成同一層的一對節點，一對之中只能有一邊有點數；戰鬥外可以免費把點數從 A 搬到 B（不需要旅館重置）。理由：變招是 build 的一部分，應該和符文一樣可以隨手試；存檔照舊是 `tree: Record<string, number>`，`validBuild` 只多一條「同對互斥」規則。資料結構（每層一個節點陣列，或 `TreeNode.pair`）交給實作者。
- 主動節點的階級成長（`ACTIVE_RANK_PCT`）保留：學會一招、越練越強是好懂的基本線。
- 洛恩 5 條分支的 4 個強化節點（劍技、堅守、星術、祈光精通）同樣改成變招節點。
- 每位夥伴的 6 個變招／機制節點清單見 §8 各角色的「變招」一行【起始提案】。

## 8. 角色核心機制與招式名冊【控制者：方向】【起始提案：內容】

規則【設計裁定】：
- 每人一個機制，一句話講得完，戰鬥畫面上有計數或標記（頭像下方的小計數、敵人身上的標記、隊伍上方的橫幅）。
- 每個機制都有**自動的基本收益**（照平常打就會累積），用心操作可以拿到更多。莎菲拉是例外：她的機制就是「換招」，但換回普通攻擊也算，所以不會空轉。
- 機制屬於基礎玩法，**會進入普通難度的模擬**（§12）；符文不會。
- 角色個性依《文風聖經》§3；機制和招式名稱、說明文字照各自的語氣表（例：莉茲的說明可以出現「成交」，凜的「還有。」）。
- 一個概念只屬於一個人：全隊防禦與魔防 → 千鶴；回復 → 瑟蕾（波比只有「隨時間」的裝置回復）；全隊攻擊、速度 → 莎菲拉；降攻 → 莉茲；降防 → 希爾薇；中毒 → 凜；睡眠 → 瑟蕾；挑釁、代受、自身防禦 → 絲嘉蕾。
- **只換屬性的招式刪掉**：屬性改由符文提供。角色只保留和身分綁在一起的屬性（諾艾兒的火冰雷、絲嘉蕾的火、瑟蕾的月之冰、波比的電）。

名冊表的「狀態」：保留（不動）、改（同一個概念、改效果，沿用圖示）、換（刪掉原本的，換成新招，需要新圖示）。

### 8.1 諾艾兒（見習魔女）—「熱度」
- **機制**：她每施放一次火或雷法術，熱度 +1；冰法術使熱度 −2。熱度 0–5，每 1 點使她的法術威力 +8%。熱度到 5 時，下一個法術「暴走」：威力 ×2，然後熱度歸零，她受到最大 HP 15% 的反噬。
- **畫面**：頭像下 5 格火苗。
- **個性**：逞強、愛現、「本小姐的雷可是很貴的」；用力過頭會傷到自己。冰是讓她冷靜下來的選擇。
- **自動收益**：照平常打火雷，熱度自己會累積。

| 招 | 狀態 | 備註 |
|---|---|---|
| 火之星彈、炎之波、業火、冰之星彈、冰縛、暴風雪、雷之星彈、天雷 | 保留 | 冰縛的減速保留（屬於冰的身分）；希爾薇的釘足箭改效果以免重複 |

### 8.2 千鶴（巫女槍兵）—「結界」
- **機制**：隊伍同時只有一個結界，新的取代舊的。結界有種類與剩餘回合：**守之結界**（全隊防禦、魔防提升）、**淨之結界**（每回合結束全隊小幅回復並解除中毒）、**雷之結界**（每回合結束對全體敵人雷擊）。她的「解放」槍技會消耗結界，剩幾回合就加幾成威力。
- **畫面**：隊伍上方的結界橫幅（種類圖示＋剩餘回合）。
- **個性**：端正、儀式感、守著神社的人；「失禮了」——先守，再一槍了結。
- **自動收益**：結界本身就是防禦；不解放也有用。

|---|---|---|
| 橫掃、旋槍、千本槍、貫槍、天之逆鉾 | 保留 | 天之逆鉾可以解放結界 |
| 結界 | 改 | 守之結界（全隊防禦與魔防的唯一來源） |
| 御神酒 | 換 | 淨之結界（新圖示） |
| 大結界 | 改 | 目前的結界效果加倍、延長 3 回合 |
| 雷神突 | 換 | 「破邪突」：解放結界的單體突刺（新圖示）；雷屬性改由符文提供 |

### 8.3 莉茲（尋寶獵人）—「銅板」
- **機制**：她每命中一段得 1 枚銅板（最多 10）。「花錢」的招消耗銅板換威力。戰鬥結束時剩下的銅板，每枚換成少量金幣。

- **個性**：三句不離錢、估價、殺價，「這個值多少？」「成交？」。
- **自動收益**：多段攻擊自己會賺銅板；剩下的換錢。

|---|---|---|
| 雙刃、潛行、尋寶直覺、疾步、幻影步 | 保留 | 疾步是唯一的自身加速（凜的隱匿已改） |

| 影刃亂舞 | 換 | 「一擲千金」（終極）：花光銅板，每枚一段 40 威力打隨機敵人（新圖示） |
| 幸運一擊 | 改 | 「大手筆」：花光銅板，每枚威力 +15% |
| 毒刃 | 換 | 「估價」：看穿目標弱點；擊倒它時銅板加倍（新圖示）。中毒歸凜 |

### 8.4 希爾薇（森林遊俠）—「瞄準」
- **機制**：連續對同一個目標出手，瞄準 +1（最多 3）；每層使她對這個目標傷害 +15%、暴擊率 +10%。換目標或目標倒下就歸零。
- **畫面**：目標身上的準星（1–3 圈）。
- **個性**：耐心、實際、像看動物一樣看戰場；「別出聲。前面有東西。」
- **自動收益**：一直打同一隻就會累積（模擬玩家本來就一直打第一隻）。

| 招 | 狀態 | 備註 |

### 8.5 絲嘉蕾（火焰騎士）—「餘燼」
- **機制**：她受到的傷害有一半存成餘燼（最多是她最大 HP 的 50%）。火焰招的 HP 消耗先用餘燼付，不夠才扣 HP；紅蓮終焉消耗全部餘燼，每存一份加一份威力。
- **畫面**：頭像下的餘燼條。
- **個性**：把每一次擋傷當成贖罪的騎士；「擋下攻擊，是我的職責。」
- **自動收益**：站前排挨打就會累積，火焰招變得不痛。

### 8.6 瑟蕾（月之法師）—「月相」
- **機制**：戰鬥中月相每回合前進一格：上弦 → 滿月 → 下弦 → 新月 → 上弦……（每場從上弦開始，完全決定性）。**滿月**她的回復 +30%；**新月**她的睡眠機率 +30%；**上弦**她的 TP 消耗 −30%；**下弦**她的冰傷 +30%。她可以用「收回」把月相倒回一格。
- **畫面**：畫面上方的月相（現在＋下一個）。
- **個性**：用月相「預報」小事，說完又收回——「剛才那句，請當作沒聽見吧。」
- **自動收益**：被動輪轉，不管就有隨機的好處；會看月相的人能把大招排在對的回合。

| 祝福 | 換 | 「收回」：0 TP，月相倒回一格（新圖示）。防禦、魔防歸千鶴 |
| 聖域 | 換 | 「滿月之夜」（終極）：接下來 3 回合月相停在滿月（新圖示） |

### 8.7 莎菲拉（沙漠舞劍士）—「拍子」
- **機制**：她這回合用的招和上一回合**不同**（普通攻擊也算一招），拍子 +1（一、二、三、四）；同一招連用就「踩空」歸零。拍子每拍使她的威力與增益效果 +10%；第四拍的下一招是「終幕」：增益改為全隊並多 1 回合，攻擊多 1 段，然後回到一。
- **畫面**：頭像下 4 個拍點，踩空時跳「這一步踩空了呀。」
- **個性**：「跟上拍子囉。」數拍子、把戰鬥當舞台。
- **自動收益**：只要輪流用招（含普通攻擊）就會累積。

| 紗之舞 | 換 | 「拍手」：0 TP，全隊絕技量表 +10、拍子 +1（「掌聲呢？」）（新圖示） |

變招：刃舞・四拍（4 段）；戰舞・熱場（另加速度）；影步斬・切分音（拍子 +2）；拍手・安可（量表 +15）；機制「即興」（同一招連用不踩空，只是不加拍）；機制「雙人舞」（終幕的增益也給下一個行動的隊友）。

### 8.8 波比（技師）—「裝置」
- **機制**：裝置招在場上放一個裝置，每回合結束自動運作；同時最多 2 個。再放同一種裝置是「改良」：等級 +1（最多 3）、回合數重置，而不是取代。
- **畫面**：頭像旁 2 個裝置格（圖示＋等級＋剩餘回合）。
- **個性**：「一下下就好」——先架設，後收成；會改良不需要改良的東西。
- **自動收益**：放了就會自己動。

### 8.9 凜—「暗記」與「還有。」
- **機制**：她可以在一名敵人身上留下暗記（同時只有一個）；她打有暗記的目標必定暴擊。她擊倒任何敵人時立刻再行動一次（每回合一次），畫面跳出「還有。」
- **畫面**：敵人身上的暗記；再行動時的「還有。」。
- **個性**：精準、短句、「還有。」是她講完一件事後再補一句的口癖。
- **自動收益**：擊倒就再動，不用任何操作。

| 招 | 狀態 | 備註 |

### 8.10 洛恩（主角）—「殘響」
- **機制**：新指令「殘響」：重現這一回合（或上一回合）隊友最後施放的一招，照那位隊友施放時的樣子（含她的符文），威力 70%，TP 由他付相同的量。觸發不會因殘響發生。
- **畫面**：指令列多一個「殘響：〇〇」，沒有可重現的招時變灰。
- **個性**：什麼都一學就會（過去每一輪的殘響），夥伴覺得不公平；他自己平平地說出來。
- **自動收益**：無（是指令，不是被動）；他原本的 5 條分支照舊，所以預設配點與五種 `HERO_BUILDS` 不受影響。

他的 21 招不收斂（§3）。精通節點改成變招節點。

## 9. 異常狀態【控制者：方向】【設計裁定：細節】

| 名稱 | 屬性 | 效果（一句話） | 持續 | 頭目 | 抗性 |
|---|---|---|---|---|---|
| 灼燒（新） | 火 | 每回合結束受到「造成灼燒那一擊」35% 的火傷；重複時只留最強的一個。 | 3 回合 | 機率減半 | `fireRes` 降低機率 |
| 凍結（新） | 冰 | 失去下一次行動；解除後 2 回合內不會再被凍結。 | 1 次行動 | 不會被凍結，改為「冰緩」：速度 −30%，2 回合 | `iceRes` |
| 感電（新） | 雷 | 受到的所有傷害 +20%。 | 2 回合 | 機率減半 | `thunderRes` |
| 流血（新） | 物理 | 每回合結束受到「造成流血那一擊」20% 的傷害；最多疊 3 層，各自計算。 | 3 回合 | 機率減半 | 無（護甲不擋） |
| 中毒 | — | 每回合結束失去最大 HP 的 10%。（不變） | 到解除或戰鬥結束 | 機率減半（不變） | `poisonRes` |
| 睡眠 | — | 不能行動，受到攻擊就醒。（不變） | 3 回合 | 機率減半（不變） | `sleepRes` |

- 灼燒與流血刻意不同：灼燒只留最強一個（適合單發大招），流血可以疊（適合多段）。這對應流亡暗道的點燃與流血。
- 【設計裁定】**持續傷害（中毒、灼燒、流血）不會叫醒睡眠**；只有命中會。理由：瑟蕾的睡眠和凜的毒應該是組合，不是互相抵銷；而且這是玩家會預期的規則。
- 【設計裁定】**異常不會自動發生**：元素傷害本身不附帶異常，只有寫明的技能、符文、變招、敵人技能會。理由：普通難度的敵人與預設配點不吃到新的隨機效果，凍結的平衡帶不受影響；而且「什麼時候會燒」永遠看得到出處。
- 【設計裁定】**增益改為取最強**：同一屬性、同方向的增益，留下比較強的那個，回合數取較長的（取代 `addBuff` 現在的「新的直接蓋掉」）。理由：現在弱的增益會蓋掉強的，是反直覺的陷阱；收斂後同概念只剩一位角色，衝突也大幅減少。
- 新的抗性沿用元素抗性，不新增詞綴鍵。理由：裝備詞綴池不變，`AFFIXES` 與第 10 項平衡帶不受影響。
- 畫面：每個戰鬥者頭上顯示異常圖示＋剩餘回合；被凍結的敵人，意圖欄顯示「凍結中」。
- 新的護盾（波比的護盾產生器、傳說符文「滿溢」）是 `Combatant` 上的一個吸收值，先扣護盾再扣 HP，戰鬥結束清除。

## 10. 和其他系統的交互【設計裁定】

### 10.1 傳說威力
- 傳說威力照舊套用（§6.6 順序第 5 步），不佔插槽。等於「裝在裝備上的固定符文」，和流亡暗道的傳奇物品同一個角色。
- 被「換」掉的招，威力改指向新的對象（物品 id 不變，存檔不受影響，只改 `POWER_LIST` 的 `skill` 與 `text`）：
  - `shade-silent-blade`（無聲之刃，原：三連刃改 4 段）→ 凜的飛針改 3 段。理由：無聲的短刃本來就是刺客的東西。
  - `mire-whisper-gloves`（沼語手套，原：衰弱咒必定中毒）→ 凜的毒針必定中毒（頭目減半）。理由：中毒歸凜。
  - 其他 12 個不變。`lg-scarlet` 指向的挑釁、`iron-bulwark-plate` 指向的鐵壁都保留。
- 新增指向技能樹招式、凜、洛恩的傳說威力**不在本次範圍**（之後可以再加，也可以指向機制，例：「熱度上限 +2」）。

### 10.2 套裝、記憶關鍵天賦、好感度
- 套裝效果只加屬性，不變。
- 記憶關鍵天賦數值不變；只有一個要改說法：`blueprint`（我來修好）「砲台威力 +30%」改成「裝置效果 +30%」。其他（`small-shrine` 開場全隊防禦、`troupe-step` 增益多 1 回合等）照舊。
- 好感度（`bond`，`2026-10-18-starlantern-affinity-expressions-design.md`）**不解鎖插槽、符文或機制**。理由：好感度 spec 的反目標是「讓某支隊伍變成必帶」；符文必須是全隊共用、和角色無關的戰利品。
- 關鍵天賦（`crit-tp`、`kill-tp` 等）照舊，而且自然和觸發符文、凜的「還有。」組合，不需要另外規則。

### 10.3 敵人
- 普通難度的敵人技能**不新增**異常（§9 的理由）。新異常在敵人身上的效果照 §9；敵人的抗性從 `EnemyDef.sec` 的元素抗性讀。
- 代受與挑釁的優先順序：挑釁 > 代受 > 原本的目標（延伸 `perform` 開頭的挑釁覆寫）。凜「隱匿」中不會被單體攻擊選中，除非全隊都在隱匿。
- 敵人的意圖仍在玩家選擇前決定（`planEnemies`）；行動時被凍結就跳過，下一回合重新計畫。

## 11. 引擎與 AI 的影響

- **決定性**：所有新的機率（異常、連鎖目標、散射、一擲千金的隨機目標）都用戰鬥既有的 `rng`，依固定順序抽；**機率為 0 的事不抽**（沿用 `combatant.roll` 的規則），所以沒有新東西的戰鬥，亂數序列和現在逐位相同。符文掉落用 `RUNE_SALT` 加鹽串流（§6.5）。禁止 `Math.random`。
- **狀態放哪裡**：角色機制放在 `Combatant` 的一個 `mech` 欄位（熱度、銅板、瞄準、餘燼、拍子、裝置、暗記）；隊伍層級的放在 `BattleState`（結界、月相、殘響可重現的招）。戰鬥結束全部清空，不進存檔（莉茲的銅板在結算時換成金幣）。
- **`skillFor` 的簽章**：要能拿到符文與變招。符文在 `fromMember` 時從 `Member.sockets` 抄進 `Combatant`（像 `powers`、`ranks`）。
- **模擬玩家 `choose`**：
  - 不需要學會用符文（模擬的隊伍沒有符文，§12）。
  - 會自然拿到機制的自動收益（熱度、瞄準、餘燼、還有。、月相）。莉茲的花錢招與千鶴的解放，`power()` 要讀「這名角色現在施放會是多少」（含銅板、結界），不然模擬會在 0 銅板時亂放大手筆；這是 `power()` 的小改，實作者決定做法。
  - 洛恩不使用殘響（預設配點不受影響）。
  - **學會用架設類技能**【控制者】：見 §12.5。理由：模擬代表「一個合理的預設配點玩家」；新名冊把價值放進結界、裝置、暗記、拍子，模擬不會用就量不到，戰力對等與平衡帶都會失真。
- **野外施放**（`engine/field.ts`）：補血技吃符文（例：月光＋擴散在野外也是全體），觸發與常駐不作用。
- **戰鬥紀錄**（`BattleEvent`）新增：異常種類擴充、`mech`（機制數值變化，用來播「還有。」「踩空」等）、`trigger`（觸發施放）、`shield`。

## 12. 平衡方法

### 12.1 原則【使用者】【控制者】
- 現在 `engine/balance.test.ts` 的全部門檻**就是普通難度的平衡帶**，凍結，只准收緊。
- **門檻凍結；量測工具（模擬玩家）可以改，但只能在「舊名冊逐位相同」的閘門之後改**【控制者】（§12.5）。理由：門檻是使用者核准的手感；工具要能量到新名冊的價值，而閘門證明換工具本身沒有移動任何數字。
- 平衡只對照預設配點（使用者先前的決定：不配點被打爆是設計意圖）。
- 普通難度的驗收＝**預設配點、沒有符文**的模擬。

### 12.2 符文怎麼被排除在普通的模擬之外
- `partyAt`、`kitParty` 建出來的成員沒有 `sockets`；新增守門測試：每一條平衡帶用到的隊伍，鑲嵌的符文數為 0，且 `choose` 從不觸發觸發符文、常駐符文。這和 `kitParty` 把傳說級掉落當稀有、不吃特殊威力是同一個先例。
- 角色機制、變招（預設配點選的那一邊）、新異常規則**會**進入普通的模擬：它們是基礎玩法。

### 12.3 做法與順序【設計裁定】
0. **先擴充模擬玩家，並通過舊名冊閘門**（§12.5），在任何名冊改動合併之前。同時用擴充後的模擬在舊名冊上錄下戰力對等的基準（§12.6），存成測試夾具。
1. **再做名冊與機制，不做符文**。每次名冊改動都要通過「戰力對等」（§12.6）。這是便宜、快速的回饋，先過了再跑完整的平衡帶。
2. 跑完整平衡帶（含 `BALANCE_REPORT=1` 列出所有數字）；超出就調新招的數字，不動門檻。
3. 再做符文。因為模擬不吃符文，這一步不應該移動任何既有的量測值；守門測試證明這件事（量測值逐位相同）。
4. 最後做建議 build 與介面。

### 12.4 新增的平衡帶（加在後面，不改舊的）
- **符文的天花板**：最強的一套建議 build（史詩階符文）＋第 14 項的 +ENHANCE_MAX 稀有套裝，頭目仍然不會一回合倒下（對應第 11、14 項）。
- **符文有價值**【控制者：量法】：每套建議 build 用魔法階符文、**用它自己的行動策略**（§16），在它的專長情境（單體頭目、多敵、持久戰之一，寫在 build 資料裡），該角色的每回合有效貢獻（§12.6 的定義）比同等級、無符文的預設配點用預設策略高至少 20%；而且整隊勝率不低於預設。理由：build 的價值取決於怎麼打，用預設策略量 build 會低估它；兩邊都用同一個貢獻帳本，數字可以直接比。這條同時是噩夢難度的前提（§13）。
- **沒有唯一正解**：任何單一符文在「一般情況」（標準目標群、魔法階）讓一招的期望輸出超過原本 1.6 倍就算失敗；在它的專長情境可以更高。
- **異常不洗版**：普通難度的頭目在一場戰鬥裡被凍結的次數有上限（例：最多被冰緩，從不被凍結，由規則保證）。

### 12.5 模擬玩家的擴充與舊名冊閘門【控制者】
- `choose` 改成「依角色的**行動策略**決定」：策略是資料裡一張短的優先順序清單，每一條是固定幾種規則之一，從上往下，第一條成立的就是這回合的行動；全部不成立就走現有的規則（絕技 → 有人半血以下就補 → 最強傷害技 → 普通攻擊）。
- 規則種類【起始提案】：`ensure-barrier`（沒有結界或剩 1 回合就架）、`ensure-device`（有空的裝置格或某裝置剩 1 回合就放／改良）、`ensure-mark`（暗記目標不存在就標第一個活著的敵人）、`alternate`（避免和上一回合同一招：在可用的傷害技裡選和上回合不同的最強一招，沒有就普通攻擊）、`spend-at`（銅板、瞄準、熱度、餘燼到門檻才用花費招）、`heal-below`（指定 HP 比例以下才補）、`strongest-damage`。每一條都是純函式、不抽亂數（`choose` 現在也不抽）。
- 預設策略（每位角色一份，屬於「標準」build）【起始提案】：千鶴 `ensure-barrier`；波比 `ensure-device`；凜 `ensure-mark`；莎菲拉 `alternate`；莉茲 `spend-at`（銅板 ≥ 6）；希爾薇 `spend-at`（瞄準 3 層才放星墜一矢）；其他人沒有額外規則。
  - **實作註記（plan 8c Task 5 修正輪 1）**：莎菲拉的 `alternate` 加上 `repeat`：可用的傷害技只有一招、且上回合用的就是它時，再放一次（踩空），不改用普通攻擊。原因：Lv 5–20 她只有刃舞，「沒有就普通攻擊」讓她每兩回合才放一次刃舞，短戰鬥裡拍子還沒累積到終幕就結束；在拍子每拍 +10%（含普通攻擊）、四拍終幕的規格數字下，戰力對等的 Lv 5 與 Lv 10 兩格無法同時通過（Lv 5 靠省 TP 偏高、Lv 10 偏低，整隊 Lv 10 也低於 −5%）。只有把拍子降到每拍 3%，或把終幕改成第三拍，才調得進去，兩者都讓機制失去意義或違反 §8.7，所以保留 `repeat`。有兩招以上的傷害技時（Lv 35 起）規則與原文相同。數字見 `retune.md`。
- **規則只認新機制**：每條規則只在該角色有對應的機制欄位（`mech`、結界、裝置）時成立；舊資料的 `turret`、`ward` 不是「裝置」「結界」，所以在舊名冊上一條也不會成立。
- **閘門測試（在任何名冊改動之前合併）**：在目前的舊名冊上，對 `balance.test.ts` 用到的每一個情境（每條平衡帶的每個隊伍、等級、敵群、種子），擴充後的模擬與舊的 `choose` **每一回合的行動逐一相同**，而且 `BALANCE_REPORT=1` 的全部輸出逐位元相同（輸出先在 HEAD 錄成夾具）。之後所有名冊改動都用擴充後的模擬，對凍結的門檻量。

### 12.6 戰力對等（±10％）與貢獻帳本【控制者】
- **比的是什麼**：每位角色「每回合的有效貢獻」，新名冊對舊名冊。貢獻 ＝ 造成的傷害 ＋ 回復 ＋ 防止的傷害。同一位角色內部刻意的角色轉換（例：瑟蕾少了防禦增益、多了月相）允許，只要她的總和在舊總和的 ±10% 內；整隊的總和要在 ±5% 內。理由：只比輸出會懲罰千鶴、絲嘉蕾、波比這種把價值改放在防護的設計；比總和才允許收斂與轉換。
- **情境**：Lv 5／10／20／35／50；每個等級用該深度的標準敵群與頭目；固定種子（沿用 `winRate` 的 `k × 7919`）；擴充後的模擬玩家。標準隊伍的五人直接量；不在標準隊伍的夥伴，用「洛恩＋凜＋她＋千鶴＋瑟蕾，她取代諾艾兒」（量諾艾兒時用標準隊伍）。舊名冊的數字在 §12.3 第 0 步錄成夾具。
- **貢獻帳本**：`EffectContext` 多一個可選的 `ledger`，只有模擬會傳；遊戲中不存在，所以遊戲行為與亂數序列不變。帳本**不抽任何亂數**：所有「如果沒有」的計算都重用這一擊已經抽好的變異值與暴擊、格擋結果，只把一個因素拿掉重算公式。沒命中（閃避）的一擊，防止量一律記 0。
  - **傷害**：`dealDamage` 回傳的實際損失（不含溢出），記給出手的人；持續傷害（中毒、灼燒、流血）記給施加它的人（狀態要記錄來源）；裝置、結界的傷害記給架設的人。
  - **回復**：`gainHp` 回傳的實際回復（不含溢補），記給施放的人；裝置、結界的回復記給架設的人。
  - **護盾**：實際被吸收的量，記給給護盾的人。
  - **增益與減益**（結界、我方防禦／魔防增益、敵方降攻）：一擊打到我方時，對每一個生效中的防護性增益或減益，各自重算「只拿掉這一個」的傷害，差額記給它的施放者（邊際計算，彼此不互相扣，順序無關）。
  - **挑釁與代受**：被轉向的那一擊，以原本的目標（敵人意圖裡的目標）用同樣的變異值重算，差額 `max(0, 原目標會受的 − 實際承受的)` 記給挑釁或代受的人。
  - **防禦指令、`taunt-guard`、`not-a-shield`、鐵壁**：同樣以「拿掉這一個因素」重算，差額記給本人。
  - **不計入**：閃避、護甲、元素抗性這類屬性（新舊相同、不是技能的貢獻）；睡眠、凍結、冰緩這類讓敵人少行動的控制（沒有決定性又便宜的反事實）。這兩項在新舊兩邊同樣不算，所以比較公平。
- 帳本本身要有測試：一場固定種子的戰鬥，帳本加總後的傷害等於敵方損失的 HP 總和、回復等於我方回復的總和；有沒有帳本，戰鬥結果逐位相同。

## 17. 留給實作者決定的部分
