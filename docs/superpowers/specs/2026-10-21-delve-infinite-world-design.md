# DELVE 無限世界 — 設計

日期：2026-10-21 · 狀態：設計待使用者審閱（已經過 builder check） · 前置：PR #298（連線 M-B1 多玩家引擎，已上線 850bb261）

## 1. 為什麼

使用者原話：「把世界像麥塊一樣做成理論上無限大的世界，並且把可探索的區域做成幾乎無盡的方式」。往旁邊一直走要遇到的是「很多可探索的東西，以及各式各樣的地城」；遠方「只是換種類和前往不同背景的世界或是城市，會遇到不同的人」；在城市裡要能「探索新的 NPC 和城市或者王國、與城市的人們相處、解任務，並且看到不同城市或是村莊的特殊建築或是文化」。

現況（master 850bb261）：
- 世界固定 4200×1200 格（`engine/constants.ts` `WORLD_W/WORLD_H`），兩端海灘外是實心牆（`World.isSolid` 把左右邊界當實心）。走完全寬約 6 分鐘（`RUN_SPEED` 180 px/s ≈ 11 格/秒）。
- 生成器 `engine/worldgen.ts`（41 個階段）幾乎每一步都讀整張圖：生態區按寬度比例擺（森林在中間、雪地 / 叢林各一邊、沙漠隨機一邊、兩端海灘、地城在一側海灘內）、液體全圖填充與模擬、村莊與地城做全域擺放。
- 存檔只存「改過的區塊」（每塊 32×32），讀檔時由種子重新生成再疊上改動（`save/serialize.ts`）。這部分天然適合無限世界。
- 大地圖 / 探索迷霧 / 液體模擬 / 鏡頭邊界 / 每欄地表與生態陣列，都假設寬度固定。

## 2. 目標

1. **左右無限、上下固定**：世界水平方向理論上無限，垂直維持現在的 1200 格（天空 → 地表 → 洞穴 → 深層 → 熔岩深淵）。難度主要跟深度走；離家鄉越遠**稍微變難，但曲線不能過度陡峭**（使用者決定，見 C12）。
2. **家鄉大陸 + 海 + 新大陸**（使用者同意的結構）：
   - 世界中央是「家鄉大陸」：就是今天的 4200 格世界，用今天的生成器、同一個種子生成，內容一格不差。
   - 兩端海灘往外原本是牆，改成**海**；渡海後是無限延伸的新大陸。
   - 舊存檔：家鄉大陸原封不動，玩家蓋的、挖的全部保留；只是邊界打開。
   - 新開的世界結構相同：出生在熟悉的家鄉大陸，往外才是新地區。
3. **遠方 = 換文化、換風景**：新大陸由一個接一個的「文化地區」組成（例：沙漠王國、雪國、東方山城、蒸汽工業區、蘑菇國度——名稱是例子，種類由 builder 定）。每種地區有自己的背景、地形、方塊、植物、怪物與天氣（各地區專屬音樂是加分項，第 2 段再決定做不做、怎麼做；DELVE 目前沒有音樂系統）。
4. **地城五花八門**：散在各地（地表、地下、空中、海底都可能），每一種有自己的結構、怪物、機關、寶箱，最深處可以放 BOSS（BOSS 本身見 §5 與另一份設計）。
5. **城市與王國能「住進去」**：
   - 每種文化有自己的**建築風格、居民穿著與種族、特殊地標**（神殿、鐘塔、市集、港口……）。
   - 城裡有新的 NPC 可以認識、相處（沿用現有 NPC 好感 / 住家系統，加上當地特有角色）。
   - 每座城有自己的任務（當地委託、附近地城、跨城送貨 / 護送等）。
   - 村莊較小，但看得出地方文化；王國是好幾座城與村連成、有名字的大區域。
6. **幾乎無盡**：城市、村莊、地城都是「文化 / 種類樣板 × 程式隨機組合」，理論上走不完；同一文化的城市看得出是同一國。
7. **走得遠也回得來**：可合成的船（渡海）、每座城市的傳送石（到過一次就能互傳）、能拖曳縮放、只畫走過地方的大地圖。

## 3. 非目標

- 上下無限（垂直固定 1200 格）。
- 遠方難到形成「牆」、或強到讓家鄉大陸沒有用處（見 C12）。
- BOSS 設計與戰鬥系統加深的細節——使用者要求，但另開一份設計（§5）；本設計只保證地城與地區有放 BOSS 的位置。
- 全面美術翻修（HUD / 選單 / 既有怪物與 BOSS 造型）——之後另做；本設計只要求新內容自帶與現有畫風一致的美術。
- 連線本身（M-B2 以後）；但本設計的世界資料形狀要讓連線能接（§7）。

## 4. 反目標（做到了也算失敗）

- **只是單純走路，幾乎看不到新東西、沒有驚喜**（使用者原話）。
- 舊玩家打開存檔，家鄉大陸有任何一格和以前不同，或蓋的房子不見。
- 走遠以後明顯卡頓、存檔爆量、或讀檔越來越慢。
- 所有城市長得一樣、只是換顏色；所有地城都是同一種房間堆疊。
- 走遠了回不了家（沒有船 / 傳送石 / 地圖就被困住）。

## 5. 使用者已決定

| 項目 | 決定 |
|---|---|
| 方向 | 左右無限，上下固定 |
| 遠方的意義 | 主要是換種類、換背景的世界 / 城市、遇到不同的人 |
| 遠方的難度 | 可以稍微變難，但曲線不能過度陡峭 |
| 遠方的獎勵 | 「不同但大致同級」：材料 / 裝備有地方特性（例：雪國武器緩速、沙漠護甲抗熱、山城武器出招不同），外加當地服裝、家具、建材、配方；隨難度小幅變好 |
| 城市要做什麼 | 探索新 NPC 與城市 / 王國、與居民相處、解任務、看特殊建築與文化 |
| 舊世界 | 原 4200 格保留在中間，兩端海灘外變海，渡海後是新大陸 |
| 失敗的樣子 | 單純走路、幾乎看不到新東西或驚喜 |
| BOSS | 要設計一些 BOSS 讓戰鬥更深入（另開設計，跟第 2 段一起做） |

## 6. Claude 代為決定（使用者可推翻）

- C1 **分三段交付，每段做完都能玩**：
  1. **無限世界底層**：世界資料改成以區塊座標存取、邊走邊生成與卸載；家鄉大陸照舊生成；兩端接上海與新大陸；船、傳送石、新地圖；存檔與舊檔相容。第 1 段的新大陸用現有四種生態，**但第 1 段上線時就要達到 C2 的驚喜密度**：把現有的結構種類（小木屋、遺跡、廢棄礦坑、密室、浮空島、遺物 / 石碑、地標、NPC 村落、矮人地廳、地城）改成能在新大陸分區塊生成，沿路散布。地區系統要預留「文化地區」的欄位，讓第 2 段直接加種類。本次只寫第 1 段的實作計畫。
  2. **文化地區與地城**：多種文化地區（背景、地形、方塊、怪物、音樂）＋多種地城（結構、機關、寶藏、BOSS 位置）。BOSS 與戰鬥深度的設計在這段開工前另外談。
  3. **城市與王國**：各文化的建築、居民、任務、地標、王國命名。
- C2 **驚喜密度**（對應反目標 1）：在新大陸用正常速度往同一方向走，**平均每 30 秒（約 340 格）至少遇到一個新東西**（地城入口、村莊、地標、遺跡、特殊地形、稀有生物……），**每 2–3 分鐘至少一次「大東西」**（城市、大型地城、新的文化地區邊界）。數字由 builder 用測試驗證（例如掃描某個種子 ±50,000 格統計）。
- C3 **過海**：海寬是幾十秒的航程，不是幾分鐘；船前期就做得出來（家鄉大陸的材料）；海上偶有小島。沒有船也能游過去但很辛苦（現有溺水規則照舊）。
- C4 **傳送石**：每座城市（第 3 段之前是新大陸上每隔一段距離的村落 / 地標）一顆；碰過就解鎖，從任一已解鎖的傳送石傳到另一顆；家鄉大陸出生點附近也有一顆。**解鎖紀錄存在世界上、全世界玩家共用**（傳送石本身是世界上的東西；連線時任何人碰過就大家都能用，客人用的就是房主世界的紀錄）。
- C5 **地圖**：小地圖與大地圖都只畫探索過的地方；大地圖可拖曳、縮放、標出已解鎖的傳送石與城市名字。探索紀錄以區塊為單位存，世界再大也不會一次配置整張圖。
- C6 **實務上的世界邊界**：「理論上無限」，但數值精度 / 存檔欄位可以設一個極遠的硬邊界（例如 ±1,000,000 格，約 25 小時走路）。到不了的距離不算違背目標。
- C7 **家鄉大陸怎麼保留**：家鄉大陸繼續用現有生成器（全圖一次生成 4200 格，數學上和今天一樣），新大陸用新的「只看種子與座標」的分區塊生成器；兩者在海裡接縫。所以不需要改寫現有 41 個生成階段，也不會讓舊世界變樣。
- C9 **接縫**：「家鄉大陸逐格相同」指的是生成器輸出（測試可比對）。執行時海水會流進原本的海灘、地底液體可能跨過接縫，這是邊界打開的正常結果，可以接受；但不能讓家鄉大陸的地形被生成器改寫，海平面與接縫的地形由 builder 安排，讓海灘大致維持原貌（必要時在海側做緩坡 / 淺灘）。玩家原本靠著邊界牆蓋的東西會露出來，可以接受。
- C10 **海底**：1200 格深度在海底下照樣延續（洞穴、深層、熔岩深淵都有）。玩家可以從地底挖過去不搭船，這比搭船慢得多，可以接受（同麥塊）。
- C11 **連線的順序**：連線 M-B2 以後的工作暫停，等第 1 段做完再接，連線設計屆時改成「按區塊座標要求差異」。第 1 段要支援多個玩家相隔很遠（各自周圍的區塊都載入、刷怪各自進行），因為 M-B1 的多玩家引擎已經上線。
- C12 **距離難度曲線**：深度仍是難度主軸，距離只是加成。加成跟「離家鄉大陸幾個地區」走、遞減成長、有上限。量級例子（builder 可調，但形狀要守）：第一個新地區約 +10%，約 10 分鐘路程外約 +25%，約 1 小時路程外約 +45%，上限約 +60%（怪物血量 / 傷害 / 防禦）。剛渡海時，帶著家鄉大陸中期裝備的玩家要打得過。掉落與寶箱的裝備等級跟同一加成小幅上升，但幅度不超過難度加成；地方特性材料是同級的不同選擇，不是碾壓。
- C8 **生成要能分區塊**：新大陸任何一格的內容只由（種子, 座標）決定，不依賴玩家先走過哪裡（連線與重生都需要）。大型結構（城市、地城）用「區域格網 + 種子」決定位置與大小，跨區塊的部分在每個區塊各自算出自己那一片。

## 7. 限制

- **存檔相容**：現有 `GEN_VERSION 7` 的世界要能直接打開，家鄉大陸逐格相同（用測試比對：同種子、同 4200×1200 範圍，新舊輸出一致）。存檔格式可以升版（目前 `SAVE_FORMAT 9`），舊檔一次轉換。
- **連線相容**：連線設計（`docs/superpowers/specs/2026-10-20-delve-coop-design.md`）原本假設客人「一次生成整張圖、比對 5016 個區塊雜湊」。改成無限後，客人要能按需生成區塊、以區塊座標要求差異。本設計要讓世界資料以「區塊座標 → 區塊」為單位存取與存檔，連線那份設計之後跟著改。單人與 M-B1 的多玩家引擎（敵人、掉落、刷怪看所有玩家）在無限世界照常運作。
- **效能**：記憶體只保留玩家附近的區塊（連線時是所有玩家附近）；遠處未改動的區塊卸載後可重算，改過的寫回存檔。讀檔時間不隨走過的距離明顯增加。
- 確定性：生成禁用 `Math.random`、超越函數要照現有 worldgen 的做法避免跨瀏覽器差異（連線風險 R4）。
- 美術全部程式繪製（Canvas2D），比照現有像素風、調色盤與 1 px 描邊；不加 npm 套件。
- 文字繁體中文寫死（delve 不走 i18n）；禁 `!important`、禁行內樣式。
- 測試：`npx vitest run`、`npx playwright test tests/e2e/delve.spec.ts --project=chromium`（CRLF 檔）。

## 8. 留給 builder

- 區塊資料結構、載入 / 卸載半徑、存檔的區塊鍵格式。
- 文化地區、地城、城市的具體種類與數量（第 2、3 段開工前各自寫進該段計畫；第 1 段不需要）。
- 地區寬度、海寬、船的配方與外觀、傳送石外觀與合成 / 生成方式。
- 驚喜密度的具體量測方法。
- 現有依賴固定寬度的系統（每欄地表 / 生態陣列、`habitatAt`、`bgBlend`、天氣、霜、發現地點、NPC 尋路、液體模擬陣列、鏡頭邊界）各自改成什麼形狀。
