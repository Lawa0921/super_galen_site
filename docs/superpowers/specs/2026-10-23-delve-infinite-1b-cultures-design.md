## 1. 為什麼

使用者回報（2026-10-23）：「如果一直往東走 過海之後新生成的地區幾乎沒有任何探索價值」。現況印證：外圍生成器（`engine/chunkgen/`）只有地形、洞穴、4 種礦、樹；沒有結構、寶箱、村莊、NPC、海島，`culture` 永遠是 null，海的 `biomeAt` 回 FOREST。所有內容（村莊、矮人廳、地城、石碑、地標、遺跡）只存在中央 4200 格。

使用者要的（原話）：
- 「當然是近乎無限的探索 和各式各樣的不同大陸文化或是海島之類的」
- 地方特色：「一些特定文化才會有的裝或是附魔或是怪物」「地貌和村莊或是城鎮」「多種建材和建築風格」
- BOSS：「機制要足夠特殊」「應該要有一些故事背景」；同意「每個文化的 BOSS 是那片土地故事的高潮，靠探索拼湊，機制跟故事綁在一起」
- 重複：「遇到同一個文化當然會覺得比較無聊 但這個勢必是有限的吧」→ 接受文化數量有限，用分支與越遠越強緩解
- 「初始之地也應該有更多種怪物或是菁英怪給玩家探索」
- 第一個新文化：「霧竹之國」（東方山城）
- 中央也要換成新生成器（2026-10-22）：連線時客人不必一次算整張中央地圖
- 菁英怪與其餘設定：「你決定設定」「可以直接開始」

## 2. 目標 / 非目標 / 反目標

**目標**
1. 世界由「大陸」與「海」交替組成，左右各自無限延伸；海上有小島。每片大陸要嘛是一個文化的國土，要嘛是荒野大陸，都有值得進去的結構。
2. 新生成器 v2 從出生點起產生整個世界（包含家鄉「初始之地」），家鄉品質不低於現在的 41 階段生成器；舊生成器只留作舊存檔一次性烘焙用。
3. 菁英怪系統（詞綴改變打法）、距離難度、初始之地 7 種新怪、玩家狀態異常。
4. BOSS 框架：多隻 BOSS、各自的召喚、場地、階段、獎勵、故事；燈籠守望者遷入框架。
5. 文化框架 + 第一個完整文化「霧竹之國」，含其 BOSS「雷獸」與「雷鈴」故事線。

**非目標（這一輪不做）**
- 第二個以後的文化（各自另開專案）；霧竹之國只做「山城」一個分支。
- 城市跨城任務、王國層級的政治、音樂系統。
- 連線 M-D 延後項（見 memory `delve-coop-mc-carry`）。
- 二進位快照、遠端外觀預測等連線效能工作。

**反目標（技術上能跑但算失敗）**
- 菁英怪只是血多、傷害高的沙包。
- 新大陸只是換顏色的地形——沒有一個值得停下來的地方。
- 家鄉變差：新世界的出生地找不到村莊、地城、石碑、礦，或洞穴走不下去。
- 舊存檔壞掉、玩家蓋的東西不見、地形在改過的格子旁邊錯位。
- 走 30 秒什麼都沒遇到（1a spec C2：約每 340 格一個新東西、每 2–3 分鐘一個大東西）。
- BOSS 是「站著互砍」，或機制跟它的故事無關。
- 客人加入時要算整張家鄉地圖（卡數秒）。

## 3. 使用者已決定（不可改）

- 近乎無限、多大陸文化與海島。
- 文化差異來自：專屬裝備 / 附魔 / 怪物、地貌、村莊或城鎮、建材與建築風格。
- 每個文化的 BOSS 有故事背景，是該地故事高潮；機制足夠特殊且與故事綁定。
- 文化數量有限可接受；用分支與遠方強化緩解重複。
- 分工：先地基（新生成器取代中央、大陸 / 海 / 島、距離難度、無限世界中的結構與聚落、第一個文化當完整樣板），之後每個文化各自一個專案。
- 初始之地也要有更多種怪物與菁英怪。
- 第一個文化是「霧竹之國」。
- 中央 4200 格也換成新生成器（1a spec 已決定的「舊存檔烘焙」方案沿用）。
- 連線固定決定（1a / 連線 spec）：客人可破壞房主建物、開房主箱子；掉落先搶先得；全員拿全額經驗；世界存在房主存檔。

## 4. 世界結構（作者決定）

### 4.1 版面
- x 軸以出生點為中心。新世界（`genVersion 8`）的出生點仍在 x ≈ 2100（保留既有座標、`X_LIMIT`、區塊鍵），但「中央陣列」不再由舊生成器整張填好，改為按需生成。
- **初始之地**：以出生點為中心、寬約 4200 格的家鄉大陸。結構比照現在：中間森林、一側雪地一側叢林、沙漠在隨機一側、兩端海灘、地城在一端海灘內。
- 往兩側：`海 → 大陸 → 海 → 大陸 …`，東西兩側各自獨立序列，全由 (seed, 序號) 決定。
  - 海寬 480–1200 格（第一道海 480–700，越遠可能越寬），每道海 1–3 座小島（寬 40–160 格），海上點位規則見 §8。
  - 大陸寬 2400–5200 格，由 2–4 個「地區」組成（地區寬 700–1500）。
- **大陸種類**：文化大陸（整片屬一個文化，地區是該文化的不同地貌）或荒野大陸（4 種基礎生態混合，結構以遺跡、地城、小屋、礦坑、隱士為主）。
- **文化指派**：第一片東大陸與第一片西大陸之中，必有一片是霧竹之國（由種子決定哪側）；另一片是荒野。更遠的大陸從「文化池」抽，相鄰大陸不重複；目前池中只有霧竹之國與荒野，比例約 1:1。之後新增的文化加入池中即可，不改版面演算法。
  - **2026-10-24 修訂（作者決定，M2 計畫）**：gen2 第 1 版（M2 凍結）只有荒野大陸；霧竹之國在 M4 以版本閘門（`ver >= 2`）開啟。理由：凍結後已進入的大陸永遠用當時的規則，若現在就把霧竹指派出去而內容 M4 才有，提早去的玩家會得到永遠空白的霧竹大陸。M4 起，「必有一片霧竹」的規則改為「離家最近、尚未進入過的那片大陸」；代價是 M4 前已經去過東西第一片大陸的世界，霧竹會出現在第二片（tier 2）。
- **層級（tier）**：大陸序號（家鄉 0、第一片 1、第二片 2…，海與島屬於它朝外那片大陸的 tier）。用於距離難度（§6.3）與戰利品等級。

### 4.2 地區 API
- `World.biomeAt(x)` 保留（基礎生態）；新增 `BIOME.OCEAN = 4`，海的欄回 OCEAN（修 1b carry：海上遠景是森林）。所有用到 biome 的地方（生怪、天氣、霜、釣魚、背景、地下主題、日誌標籤）都要處理 OCEAN。
- 新增 `World.regionAt(x)`：回 `{ landmass序號, side, tier, kind:'home'|'culture'|'wild'|'sea'|'island', culture: CultureId|null, variant, biome, x0, x1 }`。`OuterSegment.culture` 的佔位由此取代。
- 地區名稱：文化大陸用文化自己的命名池（霧竹：「XX 山」「XX 谷」「XX 之里」）；荒野與海用現有 `NAMES` 風格。大地圖要畫出外圍地區名稱（1b carry 小問題）。

### 4.3 生成器 v2 的硬性要求
- **每格只依賴 (seed, x, y)**：沿用 1a 的確定性規則（整數雜湊、禁 `Math.random`/超越函數/`**`，`chunkgen.test.ts` 的 grep 測試延伸到 v2 資料夾）。
- **沒有全域 pass**：舊生成器的全圖隨機漫步、全圖洪水填充、`LiquidSim.settle`、全圖 CA 洞穴網都要換成區域局部做法：
  - 地表：每欄由「地區地貌參數 + 噪聲」決定；地區交界 `BLEND_W` 內插。
  - 洞穴連通：每個地區保證至少一條「主坑道」從地表入口通到洞穴層（由地區參數決定，局部可算），再疊噪聲洞穴。
  - 液體：湖、地下湖、熔岩池在生成時就是靜止形狀（盆地形狀 + 平水面），不靠模擬沉降；不允許生成後相鄰欄高度不同的熔岩（1b carry）。
  - 結構：以「地區內的槽位格」決定位置（1a spec C8），每個結構由 (seed, 地區, 槽位) 算出完整藍圖與外框；生成某區塊時，蓋上所有外框與該區塊相交的藍圖。結構不能依賴其他區塊的已生成結果，只能依賴可局部算出的地表高度 / 地區參數。
  - 跨區塊物件（樹、寶箱內容、NPC、地標、石碑）的資料全部由藍圖產生，載入區塊時登錄。
- **效能**：單一 32×32 區塊生成（含結構）在開發機的中位數不超過現有 `OuterGen` 的 2 倍，最壞不超過 8 ms；新世界開局到可操作不超過現在的時間；客人加入不需要生成家鄉整片。
- 新生成器放在 `engine/gen2/`（名稱 builder 可改），舊的 `engine/worldgen.ts` + `engine/gen/*` + `engine/chunkgen/` v1 搬到 `engine/legacy/`，只被烘焙流程動態 import（不進新世界的執行路徑；能做到 bundle 分離更好，但不強求）。

### 4.4 家鄉品質清單（v2 在初始之地範圍內必須通過）
把現有 `worldgen.*.test.ts` 的意圖改寫成對 v2 的測試（在 ±2100 格範圍掃描）：
- 4 種生態都在；出生點是平坦森林；兩端海灘；地城在一端海灘內，至少 25 個房間，有召喚 / 鑰匙相關內容。
- 2–4 個村莊、至少 1 座矮人廳；地標放置率 ≥ 85%。
- 至少 3 個密室；小屋、遺跡、礦坑（mineshaft）、空島；蘑菇 / 水晶小生態；花崗岩 / 大理石；地下湖；熔岩帶。
- 14 塊燈脈石碑與 4 件遺物全部在初始之地可取得（放置規則沿用舊的「第一個同類結構或最近的小屋」精神）。
- 礦物分布與深度關係不比現在差（每種礦在對應深度帶的密度落在舊生成器的 ±30%）。
- 燈籠守望者的召喚道具材料（發光蘑菇、凝膠、金錠）在初始之地取得得到。
- 每種生態至少一條從地表走得到洞穴層的路。
- 驚喜密度（1a spec C2）：±50,000 格掃描，任意連續 340 格內至少一個「值得停下」的東西（結構、地標、小島、特殊地形），任意 1,800 格內至少一個大東西（村莊 / 城鎮 / 地城 / 神社 / 菁英守衛點 / BOSS 場地）。

## 5. 存檔與舊世界（作者決定）

> **2026-10-24 使用者決定（取代下面的「舊世界升級」與烘焙）**：「保留舊有的東西似乎沒什麼意義？可以直接替換掉」，選了「舊世界整個改用新生成器」。
> - M2 刪除舊生成器（`engine/legacy/` 的 worldgen、gen、chunkgen v1）與 M1 的烘焙升級（bake、BakedSource、LegacyMeta、`.v7.bak` 流程）。
> - 打開舊世界（genVersion 7，以及 M1 期間在開發版烘焙出來的 genVersion 8 烘焙世界）時，整個世界由新生成器依同一個種子重新產生。
>   - 地形、建物、挖掘、寶箱、液體、迷霧、地區發現、傳送碑等世界資料**全部捨棄**。
>   - 世界名稱與種子保留，玩家回到出生點。
> - 角色檔（等級、背包、裝備、技能、外觀）是另外存的，**照舊保留**。
> - 下面第 1–6 步與「M1 的舊世界升級也在旗標後面」一段只記錄 M1 做過的事，M2 起作廢。
> - 每片大陸鎖版本、版本雜湊鎖、genBlocker 拒絕更新版存檔這些規則照舊。

- 新世界寫 `genVersion 8`、`outerGen` 改寫成 `gen2` 版本號；讀檔時**比對**版本（1b carry：現在沒比對），不符時走升級或拒絕，絕不靜默用新生成器疊舊改動。
- **舊世界（genVersion 7）升級**，第一次用新版讀檔時：
  1. 先備份原檔（沿用 `*.bak` 做法），成功前不覆寫。
  2. 動態載入 `engine/legacy/`，重建舊中央 4200×1200 並把所有區塊連同寶箱、液體、NPC / 村落資料、地標、區域清單「烘焙」進存檔。
  3. 舊外圍（OuterGen v1）：舊範圍延伸到「已知最遠點」所在 v1 段落的末端。已知最遠點取改過的區塊、已發現的外圍地區、已啟用的傳送碑、玩家位置的最大 |x|。
     - 這段**不存成區塊**，繼續由 `engine/legacy/chunkgen` 即時生成（作者決定，M1 計畫）。
     - v1 本來就是純 (seed, x, y)，重算結果逐格相同。
     - 若存成區塊，存檔會隨探索距離線性變大，遠超 4 MB。
     - 代價：舊世界永遠需要 v1 外圍程式碼。它本來就是逐區塊生成，客人不必整片計算。
  4. 烘焙範圍以外接 v2 的版面，接縫一律是一道海。
  5. 舊世界從接縫往外照樣有霧竹之國與荒野大陸（文化指派規則同新世界，以接縫為起點）。
  6. 區域 ID、NPC 好感鍵等依生成順序的 ID：烘焙時把舊清單存進存檔，之後不再重算。
- **gen2 之後的內容更新（作者決定：每片大陸鎖版本）**：gen2 會一直加東西（M2、M4、之後每個文化）。
  - 存檔記錄每片「已進入」大陸（含家鄉、海與島，以 side + 序號為鍵）第一次被生成時的 gen2 版本與文化 ID。
  - 之後那片大陸永遠用那個版本的規則生成；沒進入過的大陸用最新版本，文化池的新文化只會出現在那裡。
  - 生成程式碼因此要版本閘門：新功能寫成 `if (ver >= N)`；改動既有功能時保留舊分支，不得改變已發佈版本的輸出。
  - 每個 gen2 版本要有固定種子的區塊雜湊測試鎖住（「這版的輸出不能再變」）。
  - 版面演算法（大陸 / 海的寬度與邊界）一經發佈就凍結；要改只能加新版本分支。
  - M1–M2 期間 gen2 在旗標後面，版本號在 M2 打開旗標時才定為 1，之前的輸出不必相容。
- **M1 的舊世界升級也在旗標後面**：M1 期間新世界照樣寫 `genVersion 7`、走舊生成器，舊世界照舊載入；M1 的升級只在測試與開發旗標下驗證。M2 打開旗標時新世界與升級一起上線。
- 壓縮後世界檔大小要量測，目標 ≤ 4 MB（IndexedDB + gzip，`save/storage.ts`）；超過時 builder 回報並提出做法（例如烘焙只存與 v2 不同的區塊並不適用，因為 v2 地形完全不同；可考慮每區塊 RLE）。
- 連線：烘焙過的區塊就是「改過的區塊」，走現有按區塊同步；客人與房主的 `genVersion` / gen2 版本要一致，沿用 `net/guest.ts:419` 的檢查。
- 測試處置：
  - `world.central.test.ts` 的舊中央雜湊改為「烘焙結果與舊生成器輸出逐格相同」的測試，留在 legacy。
  - `actor.golden.test.ts` 的競技場改用不依賴 `generateWorld` 的固定建構器並重錄（說明原因）。
  - `save/__fixtures__/format9/10.delve` 是 200×100 的小測試世界、不是真實存檔：測試證明它們判定為不適用烘焙、照舊以舊世界載入；烘焙改用一份正式尺寸（4200×1200）的 format 11 / v7 固定檔驗證（M1 計畫 Task 1 凍結）。（M1 preflight 裁決 P15a 修訂）
  - 其餘 `worldgen.*.test.ts` 依 §4.4 改寫成 v2 測試，原檔隨 legacy 搬走，只保留烘焙需要的。
- 1b carry 一併處理：`decodeLiquidRle` 先加總 run 長度再配置；`OuterProfile.info(x)` 快取（若 v2 沿用）；1b 開工前錄 LiquidSim 效能基準。

## 6. 怪物與戰鬥（作者決定）

### 6.1 玩家狀態異常（新）
目前敵人無法讓玩家著火 / 中毒 / 緩速 / 暈眩，新怪需要：
- `burning`（已有，來源只有熔岩）→ 開放給怪物：每 0.5 秒 2 點，3 秒，碰水解除。
- `poison`：每 0.5 秒 1 點，5 秒，可疊 3 層（各自計時）。
- `slow`：移速 ×0.6、跳躍 ×0.85，2.5 秒。
- `shock`：0.4 秒無法攻擊與使用道具（不會被定在空中）。
- HUD 顯示狀態圖示與剩餘時間；連線用 `Ws` 的本機玩家欄位同步（比照 `br` 的做法）。

### 6.2 菁英怪
- **外觀**：體型 ×1.25（判定框同比例）、詞綴顏色光環、頭上名牌「〈詞綴〉的 〈怪名〉」，兩個詞綴時寫「〈詞綴1〉〈詞綴2〉的 〈怪名〉」。出現於畫面內時有一聲提示音。
- **詞綴池**（每個都必須改變打法）：
  | 詞綴 | 行為 |
  |------|------|
  | 分裂 | 死亡時分裂成 2 隻 ×0.6 體型、各 30% 血的普通版（不再分裂、不掉菁英獎勵） |
  | 護盾 | 每 6 秒張開正面護盾 2.5 秒，期間正面傷害 ×0.1，背面與上方照常 |
  | 召喚 | 每 8 秒召來 2 隻同生態的小怪（場上同菁英召喚物最多 4） |
  | 狂暴 | 血量 ≤ 40% 時移速 ×1.5、攻擊冷卻 ×0.6，身體變紅 |
  | 吸血 | 接觸 / 投射物傷害的 50% 回血；被打中時噴血效果 |
  | 爆破 | 死亡 1 秒後爆炸（半徑 3 格、傷害 = 接觸傷害 ×2），破壞非礦物的一般方塊（不破壞箱子、床、傳送碑、BOSS 場地） |
  | 潛影 | 距離玩家 > 8 格時幾乎透明（alpha 0.15），名牌也隱藏；被打中後顯形 3 秒 |
  | 寒霜 | 攻擊附帶 `slow`；死亡留下 3 秒冰面 |
- **出現方式**：
  - 遊蕩菁英：一般生怪時有機率升格（tier 0 為 3%，每 tier +2%，上限 12%）；每位玩家周圍同時最多 1 隻（tier ≥ 2 時 2 隻）。
  - 守衛菁英：結構藍圖裡的固定點（寶物間、遺跡深處、洞窟祭壇）。不刷新，除非該結構另有規則；打倒後解鎖該處的寶箱（寶箱在守衛活著時鎖住並顯示提示）。
- **詞綴數**：tier 0 恰 1 個；tier 1 為 1 個；tier 2 為 1–2 個；tier ≥ 3 為 2 個。守衛菁英 +1（上限 3）。
- **獎勵**：必掉一件裝備，稀有度表比一般怪高一階；經驗 ×2（不受同日同種遞減）；在文化大陸另掉 1–2 個該文化的特有材料。
- 菁英不存檔（同一般怪）；守衛菁英「已打倒」要存檔（以結構 ID + 槽位為鍵）。
- 連線：`WsEnemy` 加選填欄位（菁英詞綴位元、名牌所需、護盾 / 潛影 / 狂暴狀態、BOSS 階段）；同時補上現在沒同步的 `phase` 與受擊閃爍。

### 6.3 距離難度（1a spec C12 的具體化）
- 依 tier：怪物血量與傷害 ×(1 + bonus)，bonus = tier 0：0、1：+10%、2：+25%、3：+45%、≥4：+60%（上限）。
- 戰利品物品等級 = max(既有深度公式, tier 對應的等級)，tier 1 → ilvl 2、2 → 3、3 → 4、≥4 → 5。
- 外圍地區探索經驗只在第一次發現該地區時給（修 1b carry「每 ~900 格無限可刷」）。
- 深度難度照舊。距離與深度不相乘：取「深度造成的」與「距離造成的」較大者再各加一半較小者（builder 可調，但上限仍 +60%，且要有平衡測試）。

### 6.5 BOSS 框架
- 以資料登錄 `BossDef`：種類、名稱、召喚物與召喚條件、可選場地（結構藍圖中的 BOSS 場地，或「任何地方」）、階段（血量門檻、階段名稱後綴、HUD 條顏色與刻度）、出場與擊敗文案、音效、掉落表（各自的 `BOSS_DROPS` / 裝備 / 時裝 / 首殺獎勵）、日誌條目與故事文字。
- `summonBoss`、`bossEvent`、`main.ts` 文案、`hud.ts` 階段標籤、日誌「？？？」文字、`combatDraw.ts` 的不翻面例外，全部改為讀 `BossDef`，燈籠守望者遷入且行為不變（現有測試保持綠）。
- **場地型 BOSS**：場地是結構，有邊界；BOSS 戰中玩家離開場地超過一定距離，BOSS 回復並脫戰。場地內的機關（例如雷獸的鈴）是場地物件，能存檔「已啟用」狀態。
- BOSS 狀態（階段、無敵、機關狀態）同步給客人；連線 spec 的「全員全額經驗」適用 BOSS。
- 同一 BOSS 可重複挑戰（比照守望者：同日重複經驗減半）；首殺有專屬獎勵。

## 7. 文化框架與霧竹之國（作者決定）

### 7.1 `CultureDef`（資料驅動，之後每個文化只加資料與美術）

### 7.2 霧竹之國・山城
**一眼看出來**：遠景是層疊的山與霧；上山是梯田、竹林、楓；城鎮有黑瓦飛簷、紅漆柱、紙門窗、石燈籠；山頂有鳥居與高塔（雷鳴台）。

**地貌**：陡峭山地（比現有任何生態都高、起伏大）、梯田（階梯狀平台，有水田）、竹林、楓林、溫泉（熱水池，站進去緩慢回血）、瀑布（從高處流下的水柱，生成時就是靜止形狀，可用既有液體系統）、霧（天氣 `fog` 在此地區機率高）。地下：鐘乳石窟、古礦脈（多玉鋼礦）。

**新方塊與牆**（約 14 個 tile、5 面牆；美術比照 `siteArt.ts`）：竹塊、竹梯台、黑瓦屋頂（含屋簷斜角）、紅漆木、紙門（可開關，算門）、紙窗、石燈籠（光源）、榻榻米、溫泉石、鳥居柱 / 橫樑、玉鋼礦、苔石、楓葉堆；牆：竹牆、紙牆、紅漆牆、黑瓦牆、苔石牆。全部可撿起、可合成、可用於 `housing.ts` 的房屋判定（加入 `HOUSE_WALLS`）。

**聚落**：
- 山城（每片霧竹大陸 1–2 座）：石階串起 3 層平台；市集街、刀匠鋪、藥舖、茶屋、民居 4–6 間；中央有公告板（任務）。
- 山村（每片 1–3 座）：2–3 間茅屋 + 梯田。
- 神社（每片 1 座，在最高峰）：鳥居、拜殿、鐘樓，旁邊就是雷鳴台（BOSS 場地）。
- 地區散點：路邊地藏、廢棄茶屋、竹林迷徑（有守衛菁英）、瀑布祠、石窟祭壇。

**居民**（人類，外觀用現有 miko / hakama / 斗笠 / 狐面等，加 1–2 件新服裝）：
- 刀匠：賣太刀與和弓、用玉鋼錠升級文化武器。
- 藥師：賣藥水與溫泉蛋（短效回復），收購草藥。
- 巫女：故事主線 NPC，收集雷鈴碎片、重鑄雷鈴、賣符咒。
- 茶屋老闆、旅人（一般閒聊與委託）。
- 任務沿用 collect / slay / explore / escort 模板，加霧竹專屬條目。

**怪物**（5 種 + 面具菁英）：
| 怪 | 招式 |
|----|------|
| 狐火 | 浮空鬼火，分身成 3 團（只有一團是真的），碰到 `burning` |
| 天狗 | 飛行，揮扇產生強風把玩家往後推 6 格（能推下梯田），瞬移到玩家上方 |
| 石獅 | 神社 / 城門守衛，石化時無敵，被同伴喚醒；咆哮造成 `shock` |
| 竹影 | 藏在竹林背景中，玩家經過時拔刀一閃（地面出現預警線 0.5 秒） |
| 河童 | 雨夜在水邊；把玩家往水裡拖，頭頂盤子被打中會暈眩 |
- **面具菁英**：霧竹的菁英帶能面（外觀），掉落玉鋼與「雷紋紙」。

**裝備與附魔**：
- 太刀（新 `WeaponKind` `katana`）：按住蓄力，放開時「居合」向前衝 3 格斬擊，衝刺中無敵 0.15 秒；一般點擊是快速斬。
- 和弓：弓的高階版（不新增種類），射程長、蓄力箭貫穿。
- 符咒（新 `WeaponKind` `talisman`）：消耗魔力，丟出追蹤目標的紙符，命中貼附 2 秒後爆開。
- 文化詞綴（加入 `gear.ts`，只在霧竹裝備 / 霧竹來源掉落出現）：
  - 「狐火」字首：命中時讓目標著火，著火的敵人死亡時火焰跳到最近的敵人。
  - 「鈴鳴」字尾：每第 5 次命中讓目標暈眩 0.5 秒（BOSS 0.2 秒）。
  - 「霧隱」字尾：在霧或雨天時閃避率 +8%。
- 時裝：羽織（新外套）、天狗面（新帽）、能面（菁英掉落）、雷獸角飾（BOSS 首殺）。

**故事：雷鈴**（6 塊霧竹石碑 + NPC 對話交代）
- 很久以前，山中的雷獸每逢雷雨下山。神社的初代巫女鑄了「雷鈴」，鈴聲能讓雷獸僵住，最後把牠封在雷鳴台。
- 近年鈴被盜走並摔成 5 片，雷雨越來越頻繁，天狗與狐火在山裡作亂。
- 玩家從巫女那裡接主線，5 片碎片分散在：城鎮委託報酬、石窟祭壇（守衛菁英）、瀑布祠、天狗頭目（菁英）身上、竹林迷徑深處。
- 集齊後巫女重鑄雷鈴（召喚物），在雷鳴台使用即開戰。

**BOSS：雷獸**（場地型，雷鳴台）
- 場地：山頂平台，四角各有一座「鈴燈籠」（場地物件）。
- 第一階段：雷獸在場上奔跑跳躍，召落雷。落雷前 0.8 秒地面出現預警光柱；落雷會**擊碎玩家放置的方塊**（不碎天然地形與場地），逼玩家不能躲在掩體後面。雷獸蓄電時身上發光，此時若在某座鈴燈籠旁敲鈴（使用鍵），雷獸僵直 3 秒並受到 ×2 傷害；敲過的燈籠冷卻 12 秒。
- 第二階段（≤ 50%）：雷雲籠罩全場，落雷頻率加倍並連成直線；雷獸會先破壞一座鈴燈籠（玩家可以搶先敲它打斷）；必須依序敲兩座燈籠（順序由雷獸身上的紋路提示）才會僵直。
- 擊敗：雷雨停、霧散，巫女有專屬對話；掉落太刀「鳴神」（唯一）、雷獸角飾、玉鋼、雷鈴可留著重複召喚。
- 連線：任何玩家都能敲鈴；落雷預警與擊碎方塊都由房主決定並同步。

**故事進度與連線（作者決定）**
- 故事進度是**世界**的狀態（跟 `bossesDefeated` 一樣存在世界檔），不是角色的。
- 雷鈴碎片撿到時不進背包，直接記入世界的「奉納」計數（全隊共享，HUD / 日誌顯示 n/5）。客人離開也不會帶走進度。
- 雷鈴重鑄後，任何玩家找巫女都能領一個雷鈴（召喚物；背包裡已有就不再給）。
- BOSS 掉落組數 = 場地內參與戰鬥的玩家數，每組落在各自玩家附近；撿取照連線規則先搶先得。這條同時適用燈籠守望者。

### 7.3 重複與遠方
- 雷鈴主線**每個世界只有一次**，放在第一片霧竹大陸（離家鄉最近的那片）。
- 更遠的霧竹大陸有自己的城鎮、神社、雷鳴台與巫女，但沒有碎片線。那裡的巫女直接給雷鈴，前提是世界已重鑄過雷鈴；否則她會指路到第一片。
- 同一文化再次出現時 tier 更高：怪更強、詞綴更多、裝備等級更高；城鎮名字與佈局不同。
- 每片霧竹大陸的雷獸各有一次「首殺獎勵」，按大陸鍵記錄。首殺掉 tier 對應的裝備與玉鋼。
- 「鳴神」是每個世界的唯一：第一次擊敗必掉，之後每次 10% 機率。
- 分支（例如霧竹的「竹海漁村」「雪嶺寺」）留給之後的專案；框架要讓分支只是另一組地貌參數 + 聚落藍圖。
