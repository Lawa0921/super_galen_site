## §0 定案（和下文衝突時以本節為準）

1. **位置**：冒險者公會（`ui2/scenes/guild.ts`）新增指令「委託」，**排在指令列最後、「冒險者手冊」之後、「離開」之前**。story-world §11.3 要求「召回」與「冒險者手冊」入口沿用、不重排；e2e 以 Enter 選第一個指令（編隊，`tests/e2e/starlantern.spec.ts:312-315`），放最後不動任何既有游標位置。【控制者＋設計裁定】
2. **換新的節奏：每次回城換一次布告**。布告在 `arrive()` 把日子往前推之後貼出，以**那一天**（`story.day`）為種子的鍵。住旅館也會過一天，但**不換布告**：換布告只看「從迷宮回來」。理由：日曆規則是「一趟出發＝一天」（`engine/calendar.ts:1-7`），委託是冒險者的工作，跟著出發走；若跟著日子走，住四晚旅館就能刷布告。【設計裁定】
3. **布告與手上的委託**：布告 3–5 則（看評等，§6.3）；手上最多 3 件（三燈起 4 件）。**沒接的**在下次回城被換掉；**接了的**一直留著，直到回報或放棄。放棄免費、不扣功績，那一則不會回到布告上。【設計裁定】
4. **五種委託**（§5），全部用既有系統算進度，**不在戰鬥裡加任何程式**：
   - **討伐**：打倒某一種怪物 N 隻（圖鑑 `felled` 的差值）。
   - **掃蕩**：打倒某地區的原生怪物合計 N 隻（接下時凍結那份物種清單，加總 `felled` 的差值）。
   - **懸賞**：打倒某一隻守關者或頭目 1 次（`felled` 的差值）。世界觀照 story-world §3.1：「吞了太多記憶的怪物」。
   - **探路**：走到某地區的第 D 層（`dungeon.reached`）。
   - **收購**：交出某種素材 Q 個（回報時從倉庫扣）。
   - 第一版**不做**「不准用 X」這類限制條件：`Run` 不存檔，要追蹤一趟之內的事就得在戰鬥與移動裡加程式；留接口（§12.4）。【控制者＋設計裁定】
5. **只出現見過的東西**：討伐、懸賞的目標必須已上線（`listedEnemy`）而且圖鑑 `seen ≥ 1`；掃蕩至少兩種原生見過；收購的素材必須屬於某隻 `felled ≥ 1` 的物種的掉落，或是已到過的地區的地區素材。所以委託的文字永遠不會寫出沒見過的名字；「？？？」只用在評等頁的「還沒開放」的列與指名委託的鎖（§8.6）。【控制者】
6. **排除人的殘影與夥伴的故事物種**：`remnant: true` 的 13 種與帶 `lore` 的守關者、頭目一律不進任何委託；燈喰之母（終幕專屬）與劇情戰的敵人（`story: true`）、部件（`rank: 'part'`）也不進。理由：名冊 spec §4.1「打倒是放下，不是殺死」，公會對夥伴的故人發懸賞會把她們的過去變成反派。【設計裁定】
7. **報酬**：金幣、素材（精華、稀有素材、無主碎片）、符文、功績。數字是 §6 的公式，**全部在貼出布告時就算好、存在委託裡**，回報時一次都不抽亂數。收購的報酬是「貨物賣價 × 1.6」的金幣，不給素材。【控制者＋設計裁定】
8. **公會評等**：功績累積到門檻就升一級，共五級：**見習、一燈、二燈、三燈、四燈**（公會在失憶登記表的角落蓋燈印；安娜那一代「一起下去的，算同一盞燈」只在她交還之後的台詞裡回呼，招呼與布告不提）。評等決定布告則數、可出現的種類（懸賞從一燈、頭目懸賞從二燈）、手上上限，每升一級發一次賀禮（§6.3）。評等只升不降。【控制者＋設計裁定】
9. **不會無限循環**（§10）：能交的貨只限 `monster`、`region`、`trophy` 三種素材，全部只能在迷宮裡打到；店買不到、鍛造做不出、拆解拆不出。報酬的素材（精華、稀有、碎片、符文）一個都不是能交的貨。一則委託只能回報一次；布告一天只貼一次；賀禮每級只發一次。測試照名冊 PR C 的 `engine/forge/economy.test.ts` 寫法另開 `engine/guild.economy.test.ts`。【控制者】
10. **委託人**：既有的五位鎮民，各管一兩種（§7.1）：安娜（懸賞）、瑪莎（討伐）、葛倫（探路、掃蕩）、歐里克（收購怪物素材）、多蘭（收購地區素材與戰利品）。不新增 NPC：之後的 NPC 立繪項目要畫的人不變（story-world §11.4）。布告上的文字是委託人**留在布告欄上的紙條**，所以委託人不必在公會現身；回報時安娜轉交報酬與委託人的回信。【控制者＋設計裁定】
11. **指名委託**（PR E）：五位鎮民各一則固定的多步委託，條件是那位鎮民的碎片**已交還**（`story.returned`）而且評等 ≥ 二燈。這就是 story-world §11.3「把交還擴成多步任務」的落點，只**接在交還之後**，不改寫任何已播過的場景（6c 寫作計畫 :563）。【設計裁定】
12. **夥伴的一句話**：回報的委託在某地區（目標的地區），而那個地區是某位夥伴被救起的地方（`data/meetings.ts`），她又在場上，她就說一句。六個地區各一句、只寫現在，不碰記憶內容，所以不需要閘門。**不給好感度**：好感 spec 的四個來源與「送禮速度不變」是既有的契約，委託不是第五個來源；接口留著（§12.5）。【控制者＋設計裁定】
13. **種子**：新串流 `guildRng(state, day) = mulberry32(mix(state.forgeSalt ^ GUILD_SALT, day))`，`GUILD_SALT = 0xb5c0fbcf`（SHA-256 的第三個常數 K[2]；八個初始字、K[0]、K[1] 已用掉，`engine/loot/drops.ts:195-197`）。它只在貼布告時用；`game.rng`、`lootRng`、`memoryRng`、`trophyRng`、`runeRng`、`forgeRng`、`absorbRng`、詞綴串流的抽取次數一次都不變。【控制者＋設計裁定】
14. **存檔**：`GameState.guild?: GuildState`，可選；`SAVE_VERSION` 維持 9；不寫遷移（遊戲還沒上線）。`isValid` 檢查形狀，`loadGame` 在驗證之後呼叫 `repairGuild` 丟掉目標已不存在的委託（照 `repairBestiary`，`engine/save.ts:332`）。【控制者】
15. **開關**：`GUILD_LIVE`（`data/guild.ts` 的 `GUILD_SWITCH.live`，照 `BOND_SWITCH`；PR D 之前是 `false`）。關著的時候沒有「委託」指令、不貼布告、不寫 `guild` 欄位；開著但還沒解鎖時（`story.act1Cleared` 為假），指令在、按下去只有安娜說一句，**也不寫任何欄位**。兩種情況下存檔、模擬、sim gate、舊戰鬥雜湊、地圖快照、潛行快照都和今天逐位元相同（§9.5）。【控制者】
16. **解鎖**：`story.act1Cleared`（第一幕結束、第一次打倒第三層的頭目）。理由：那之前的玩家還在學走路，布告欄只會讓第一個小時更擠；第一幕之後鎮上的生活才開始。【設計裁定】
17. **迷宮裡看得到進度，但不另開視窗**：委託在戰鬥中達成時，勝利結果多一行「委託達成」；探路在換層時接在樓層名後面；迷宮選單加一個唯讀的「委託」頁。回城時，在「帶回來的東西」那一句之後說一句「有 N 件委託可以回報了」，城鎮選單的公會那一列標「新」。【控制者＋設計裁定】
18. **美術**：第一版**不需要任何新圖**。目標的圖沿用（敵人圖、素材圖示、地區特性圖示），委託種類寫成文字標籤；評等章與種類小圖示是新美術類型，列為 PR F，**要使用者先核准風格樣本**，沒核准之前只用文字，絕不用佔位圖（§11、§14）。【控制者＋設計裁定】

## 1. 為什麼要做

- 公會的世界觀早就寫好了：碎片交易所、物歸原主、失憶登記、召回、**懸賞**（story-world §3.5）。目前公會只有前四樣；懸賞與任務是第 2 項，一直留著接口（`TownFragmentDef.questHook` 有值但沒有任何程式讀它，`data/story/fragments.ts:34`）。
- 名冊上線之後有 100 種敵人、11 隻守關者、28 隻頭目、98 種新素材。玩家缺的是**下去的理由**：「這趟要去哪、打什麼」現在只有記憶碎片與到達深度在回答。委託把這些內容串成短期目標，讓同一個地區值得再去一次。
- 《世界樹迷宮》的「酒場委託」是遊戲介面 spec 當時刻意留到之後的東西（`specs/2026-10-15-starlantern-game-ui-design.md` §1「不在這次範圍」）。

## 2. 目標、非目標、反目標

**目標**
1. 每次回城，公會給 3–5 個「這趟可以順便做」的短期目標，用到名冊的怪物、守關者、頭目、素材與地區。
2. 委託有人、有故事、有實質報酬，不做純收集（story-world §11.3 的反目標）：每一則都是某位鎮民的紙條，回報時有回信。
3. 公會評等給一條看得見的長線：越做越多、越做越難、每一級有一份賀禮。
4. 指名委託把五位鎮民的交還接成第二段（PR E）。
5. 開關關著或解鎖之前，遊戲逐位元不變。

**非目標**
- 採集、難度限定裝備、NPC 立繪、劇情美術（只留接口，§12）。
- 一趟之內的限制條件（「不用歸還之燈」「不帶某人」）：第一版不做（§0 第 4 條）。
- 噩夢、地獄專屬的委託：第一版的委託不看難度，任何難度打倒都算（§12.3 是接口）。
- 新增 NPC、新增劇情場景（指名委託的完成對話在公會裡用對話框說，不是 `SceneId` 場景）。
- 好感度的新來源（§0 第 12 條）。

**反目標**（做出來能動也算失敗）

| 失敗樣態 | 為什麼是失敗 | 怎麼防 |
|---|---|---|
| 刷錢迴圈 | 經濟壞掉，金幣失去意義 | 能交的貨全部只能打到；報酬素材不是能交的貨；一則一次、一天一張布告（§10 的測試） |
| 布告劇透沒見過的怪物 | 圖鑑的「沒見過就看不到」承諾 | 目標只取 `seen ≥ 1`；文字只從資料組字串；測試掃一千個種子（§9.2） |
| 公會懸賞夥伴的故人 | 把夥伴的過去寫成反派 | 殘影與 `lore` 物種一律排除（§0 第 6 條） |
| 必須照著委託走才玩得下去 | 委託應該是「順便」 | 報酬是額外的，不是推進劇情的條件；沒有限時、沒有失敗懲罰 |
| 刷布告 | 一直回城重抽直到出現最好賺的 | 換布告要真的下去再回來（一天、一趟）；報酬依目標本身定，不依玩家想要的定 |
| 介面擠進一堆新元件 | ui2 的一致性 | 只用 `MenuView`、`win`、`confirmBox`、手冊式的分頁與詳細欄（§8） |
| 佔位美術 | `AGENTS.md` Game Art Asset Policy | 第一版零新圖；新圖走 PR F 與使用者核准（§11） |

## 4. 核心循環

```
回城 ─→ 公會貼出新布告（3–5 則，看評等）
  │        │
  │        └─ 「委託」→ 看紙條 → 接下（手上最多 3 件）
  │
出發 ─→ 迷宮裡打怪、往下走、撿素材
  │        └─ 達成時：勝利結果／樓層名多一行「委託達成」
  │
回城 ─→ 「有 N 件委託可以回報了」；公會那一列標「新」
           └─ 回報 → 委託人的回信 → 報酬 → 功績 → （升級）安娜蓋燈印、發賀禮
              （沒接的舊布告在這時被換掉）
```

- 一趟可以同時推好幾件；委託的目標本來就在玩家這一段會去的地方（只取見過的、到過的）。
- 委託沒有期限、沒有失敗；最壞的情況是放著不做，或放棄。
- 評等是長線；指名委託（PR E）是鎮民的第二段故事。

## 5. 委託種類

所有種類的共同欄位見 §9.3。下面的 N、Q、D 都是【起始提案】。

### 5.1 討伐（`hunt`，委託人：瑪莎）
- **目標**：一種一般怪物 `S`：`listedEnemy(S)`、不是頭目、沒有 `rank`、不是 `story`、不是 `remnant`、`bestiary[S].seen ≥ 1`。
- **數量 N**：舊的 8 種 6 隻；名冊依帶：B、C 帶 5 隻，D、E 帶 4 隻，F 帶 3 隻；地區原生 4 隻。
- **進度**：`felled(S) − base`，`base` 是接下時的 `felled(S)`（沒有紀錄算 0）。
- **任何難度、任何地區打倒都算**；召喚出來的也算（圖鑑本來就算）。
- **委託深度**（算報酬用，§6.1）：名冊一般怪取 `BAND_DEPTHS[band][0]`（`engine/story/handbook.ts:168`）、地區原生取 4、舊的 8 種取 2。

### 5.2 掃蕩（`sweep`，委託人：葛倫，一燈起）
- **目標**：一個地區 `R`（不含本道）：`reached[R] ≥ 4`，而且 `R` 的原生物種（`home === R`、上線、非殘影）至少兩種見過。
- **數量 N**：8 隻，合計。
- **進度**：接下時把「`R` 的原生、上線、非殘影」物種清單凍結進委託（`ids`），進度 = `Σ felled(ids) − base`。之後上線的新物種不算（不會因為資料更新而突然完成）。
- **委託深度**：`min(reached[R], 30)`。

### 5.3 懸賞（`bounty`，委託人：安娜，一燈起；頭目二燈起）
- **目標**：一隻守關者（`rank: 'warden'`）或頭目（`boss: true`）`B`：上線、見過、不是殘影、沒有 `lore`、不是 `lantern-mother`。頭目另要求它所在的層 ≤ 那個地區的 `reached`（玩家能再走過去：本道從任何深度出發，地區從 5 的倍數出發，`engine/dungeon/run.ts:94-99`）。
- **數量**：1。進度 `felled(B) − base`。
- **世界觀**：story-world §3.1 的「吞了太多記憶的怪物」，紙條寫「這一隻吞得特別多」；不寫數值、不寫詞綴。
- **委託深度**：它在表上的第一個深度（`hauntsOf` 用的同一張表：`MAINLINE_BOSSES`、`REGION_BOSSES`、`MAINLINE_WARDENS`、`REGION_WARDENS`）；預設的燈喰之獸取 5。
- **布告的第一格**：評等 ≥ 一燈而且候選不是空的時候，第一格固定是懸賞（「今日懸賞」），其餘格子照權重抽。

### 5.4 探路（`scout`，委託人：葛倫）
- **目標**：一個地區 `R` 與深度 `D = reached[R] + k`，`k` 由 `guildRng` 在 3–5 之間抽；`D ≤ MAX_REACHED`（250）。本道一律可出；地區要 `reached[R] ≥ 2`（真的去過）。
- **進度**：`reached[R]`（絕對值），`≥ D` 就達成。顯示「最深 12／15」。
- **委託深度**：`D`。
- 本道在第一次通過終幕之前，`D` 不超過 29（第 30 層是終幕；委託不替劇情催促玩家）。

### 5.5 收購（`deliver`，委託人：歐里克或多蘭）
- **能交的貨**：`MaterialKind` 是 `monster`、`region`、`trophy` 的素材，而且**認得**：
  - `monster`、`trophy`：某個 `felled ≥ 1` 的物種的 `drops` 裡有它；
  - `region`：那個地區 `reached ≥ 2`。
- 委託人：`monster` → 歐里克（店裡收怪物素材轉賣）；`region`、`trophy` → 多蘭（打鐵要用）。
- **數量 Q**：`clamp(round(120 / price), 2, 8)`；戰利品固定 2（它也是專屬獨特的製作材料，要 5 個，不讓收購把它吃光）。
- **進度**：倉庫裡現有的數量（`inventory[M]`，即時，不凍結）；顯示「持有 3／5」。迷宮裡撿到、還在背包裡的不算（回城存進倉庫才算）。
- **回報**：從倉庫扣 Q 個；**不記進 `sold`**（`sold` 是店的解鎖，委託不是賣給店）。
- 不能交：`essence`（拆解得到，等於能用金幣買）、`junk`、`rare`（報酬用的貨）、`keepsake`（送禮與遺物的規則）、消耗品、碎片、鎮民碎片。

### 5.6 權重與組成（【起始提案】）
- 每一格先抽種類，再在那種類的候選裡均勻抽目標；同一張布告不出現兩則「同種類、同目標」（重抽，最多 8 次，抽不到就留空）。候選空的種類權重視為 0。
- 權重：討伐 3、收購 3、探路 2、掃蕩 2、懸賞 2（各自的評等門檻之下是 0）。
- 委託人由種類（與收購的素材種類）決定，不抽。
- 紙條的文字變體：`variant = day % 2`（不抽）。

## 6. 報酬、功績與評等

### 6.1 報酬（【起始提案】）
`d` = 委託深度（§5），`lv(d) = min(d, 60)`。

| 種類 | 金幣 | 素材 | 符文 | 功績 |
|---|---|---|---|---|
| 討伐 | `round(N × (8 + 2.5 × lv))` | `d < 15` 魔法精華 ×1；否則稀有精華 ×1 | 無 | 2 |
| 掃蕩 | `round(70 + 12 × lv)` | 稀有精華 ×1 | 無 | 3 |
| 懸賞（守關者） | `round(120 + 18 × lv)` | 無主碎片 ×2（等級由 `shardGrade(d, guildRng())`）＋古代齒輪 ×1 | 二燈起、`runesOpen` 時 1 個 | 5 |
| 懸賞（頭目） | `round(180 + 24 × lv)` | 無主碎片 ×2＋`d ≥ 15` 星燈之淚 ×1／否則古代齒輪 ×1 | 同上 | 6 |
| 探路 | `round(50 + 10 × lv)` | 歸還之燈 ×1 | 無 | 3 |
| 收購 | `round(1.6 × Q × price)` | 無 | 無 | 2 |

- **符文**：`id` 由 `guildRng` 從 `RUNE_STOCK` 之外的一般符文池均勻抽（池子由計畫 A3 對照 `data/runes.ts` 寫死成清單），階級依 `d`：`< 15` 魔法、`< 30` 稀有、以上史詩；不出傳說。回報時照既有的 `RUNE_STACK` 規則入袋（超過就付賣價的金幣）。
- **碎片**照 story-world §11.3「懸賞的掉落要包含多片無主碎片」：兩片，等級在貼布告時就抽好、寫在委託上，玩家看得到「清晰的碎片 ×2」。
- 數字全部寫在委託裡（`reward`），回報只是照付；之後改公式不影響已經貼出的委託。

### 6.2 為什麼這樣定
- 討伐的金幣大約是那幾隻怪本身掉的錢的兩到三倍；收購是賣給店的 1.6 倍。委託是「順便」，報酬讓順便值得，但不取代下迷宮本身的收入。
- 懸賞的碎片讓「懸賞＝吞了很多記憶的怪物」在報酬上也成立，而且流進既有的碎片交易所（賣、吸收）。
- 平衡不是優先：計畫只做 §10 的正確性檢查，加一條寬鬆的上限測試（一張布告的金幣合計不超過 `BOARD_CAP(d)`），超過就調公式一次，不做平衡帶。

### 6.3 公會評等

| 評等 | 功績門檻 | 布告則數 | 手上上限 | 新開的種類 | 賀禮（升到這一級時發一次） |
|---|---|---|---|---|---|
| 見習 | 0 | 3 | 3 | 討伐、收購、探路 | ── |
| 一燈 | 12 | 4 | 3 | 掃蕩、懸賞（守關者） | 歸還之燈 ×2、300 G |
| 二燈 | 40 | 4 | 3 | 懸賞（頭目）、懸賞附符文、指名委託 | 復活羽毛 ×1、星燈之淚 ×1 |
| 三燈 | 100 | 5 | 4 | ── | 王者之鱗 ×1、鮮明的碎片 ×1 |
| 四燈 | 200 | 5 | 4 | 每張布告多一則懸賞（兩格固定懸賞） | 星燈之淚 ×2、1000 G |

- 評等由功績推導（`rankOf(merit)`），不另存；另存 `paid`（已發到第幾級的賀禮），所以重新讀檔、或之後調門檻都不會重發。
- 升級在回報那一下判斷；一次跨兩級就依序發兩份。
- 評等頁列出下一級的門檻與「新開的東西」；還沒到的級的種類名稱照寫（不是劇透），指名委託在鎮民碎片交還前顯示「？？？」（§8.6）。
- **獨特的報酬**：第一版用評等的好處（則數、上限、種類、四燈的雙懸賞）與賀禮當獨特報酬，不新增裝備或道具（新道具要新圖）。難度限定裝備之後掛在四燈與高難度懸賞上（§12.3）。

### 7.3 寫作規則
- **放哪裡、誰檢查**：照好感度的先例（`data/bond.zh-TW.ts`），委託的文字放 `data/guild.zh-TW.ts`，並併進 `voiceGates.ts` 的 `storyTexts()`（和 `BOND_SCENES` 一樣），鍵的前綴 `guild.` 加進 `voice.test.ts` 的 `POLISHED`。所以 `telegraphBreaks`、「……」預算、語尾助詞預算（`VOICE`）、兩字台詞、`MAX_LINE_CHARS`（60）、zh-TW 排版（不用拉丁字母、阿拉伯數字、半形標點；數字用 `numeral()` 寫國字）這些既有的檢查自動涵蓋它。
- **語氣**：日系 RPG 的日常，輕快、有梗、個性鮮明（聖經 §2.5）。笑點來自鎮民的固定梗：歐里克每次換的收購名目、安娜的紅筆與打勾、瑪莎的日記畫圈、葛倫的「別逞強」變奏、多蘭的一個字。
- **「……」**：紙條、回信、評等與介面字串**一個都不用**（手冊類文字，聖經 §2.3）；安娜與夥伴的台詞也不用（整個功能零個，比聖經嚴，理由是這些句子會反覆出現）。
- **驚嘆號**：鎮民只給歐里克；夥伴只給 `LOUD` 的人（`story.test.ts:2088`：諾艾兒、波比、莎菲拉、莉茲），每句最多一個。
- **反覆播放**：紙條與回信會在不同的日子重複出現，照招呼的規則（`story.test.ts:1687-1693`）不寫一次性的說法（「今天剛」「剛醒來」）；也照城鎮台詞的規則不點名凜以外的夥伴（`:1695`），因為隊伍是誰不一定。
- **稱呼**：紙條寫給「冒險者」或不稱呼（紙條是貼給所有人看的）；回信也**一律不稱呼**，因為葛倫（小子／洛恩）、多蘭（拿劍的／洛恩）的稱呼依交還而變，而回信不依交還分讀法。
- **禁區**：紙條與回信不依交還分讀法，所以**交還之前與之後都要成立**，直接套用招呼的禁字（`story.test.ts:1678-1685`）：
  - 歐里克：`女兒|丫頭|帽子`；安娜：`緹雅|冒險者的時候|當過|隊長`；葛倫：`見過|上一輪|錯覺|耳熟|十七`；多蘭：`拿劍的|洛恩|師父|聽鐵|鐵唱|火候差`；瑪莎：`丈夫|他走的|路上小心`。（指名委託在交還之後，見 §7.5。）
  - 全部：`story.test.ts` 的 `SPOILERS`（`守燈人`、`靜鐘會`）、`RIN_SECRET_TERMS`、無條件字串的禁字（`解散|散了|選擇|靜鐘會|刺客`，`:1614-1617`），加上名冊 A5 的名字掃描清單（`艾斯特拉`、`燈喰之母`、`撤退`、`公主`、`新月`、`滿月`、`債` 等）。委託文字沒有閘門，只能寫無條件也安全的內容。
  - 不寫「欠公會」這類句子（`欠(公會|著|的|錢|帳)`，`:1675`）。
  - 領路的規則（帳本 I-126）同樣適用：不寫 `求救 求助 呼救 訊號 救命`；委託是生意與日常，不是求救。
- **插槽**：`{target}` 是敵人或素材的名字（`ENEMIES[id].name`、`MATERIALS[id].name`），`{place}` 是地區名（`REGIONS[r].name`）或「本道」，`{n}` 由 `numeral(n)` 寫成國字。**深度不進紙條**（「第十五層」這類數字只在介面欄位顯示，`T.ui2.board` 用阿拉伯數字，照手冊的「本道 第 15 層」寫法），紙條只說「那一層」「門那頭」。名字可能很長（名冊最長的名字），紙條的版面要容得下（§8.3），而且插入後整句仍 ≤ 60 字（W1 的測試用最長的名字填）。
- **夥伴的一句話**：只寫「現在的她對那個地方的反應」，不碰記憶碎片的內容、不提故人、不提她為什麼在那裡被救起。沒有閘門，所以她的 `REVEALED` 詞（`story.test.ts:1009-1047`）一個都不能用：例如希爾薇不能說沼澤原本是林子（第 1 片）、莎菲拉不能說熾焰之地是被吞的沙漠（第 5 片）、莉茲不能說櫃檯與瓶罐（第 1 片）、絲嘉蕾不能說誓言（第 1 片）、千鶴不能說小祠不在了（第 4 片）、諾艾兒不能說星火（第 3 片）。稱呼照她集滿前的那一版（瑟蕾、諾艾兒、絲嘉蕾集滿前後稱呼不同；本文的六位裡諾艾兒「喂，歸來者」、絲嘉蕾「洛恩閣下」），或乾脆不稱呼（優先）。條件：她 `recruited`、在場上（`party.grid`），而且回報的委託的地區是 `MEETINGS` 裡她的地區。同時符合的人只說第一個（`MEETINGS` 的順序），不抽亂數。

### 7.4 冷讀（計畫的 W1–W7）

## 9. 決定性、存檔、開關

### 9.1 貼布告
- **何時**：`arrive()` 推進日子之後（`engine/game.ts:1511` 之後），`GUILD_LIVE && act1Cleared` 時呼叫 `postBoard(state)`；打開布告時若 `guild` 不存在（解鎖後還沒回過城，例如解鎖那一趟就是終點）就以今天補貼一次。兩處都以 `dayOf(state)` 為鍵，同一天貼兩次結果相同（冪等）。
- **怎麼抽**：`guildRng(state, day)`（§0 第 13 條）。抽的順序：每一格依序「種類 → 目標 →（探路的 k）→（懸賞的碎片等級 ×2、符文 id）」；權重、候選清單、重抽都在 `engine/guild.ts` 的純函式裡，只讀 `state`。
- **讀檔一致**：布告寫進 `state.guild`，跟著下一次城鎮存檔一起存。`toTown`／`arrive` 本身不存檔；若玩家在回城之後、任何存檔之前重新整理，就回到出發前的存檔（照今天的行為），那時的布告也是出發前的那一張，一致。
- **在迷宮裡重新整理**：`Run` 不存檔，回到城裡的存檔；圖鑑、到達深度、倉庫都一起回去，委託的進度（全部由它們推導）自然一致。

### 9.2 進度不抽亂數
- 進度由 `progressOf(state, quest)` 純函式算：圖鑑 `felled`、`dungeon.reached`、`inventory`。戰鬥、移動、掉落的程式**一行都不改**；只有 `submitRound` 在 `noteFelled` 之後多讀一次（§8.5），`changeFloor` 之後多讀一次。
- **守門測試**（`engine/guild.guard.test.ts`，照 `engine/runeEconomy.guard.test.ts` 掃原始碼）：`engine/guild.ts` 不提 `this.rng`、`lootRng`、`memoryRng`、`trophyRng`、`runeRng`、`spotRuneRng`、`forgeRng`、`absorbRng`、`affixRng`；`mulberry32(` 只出現在 `guildRng` 一處。另一條 Game 層的測試：注入會計數的 `game.rng`，接下、放棄、回報、貼布告、打開布告的前後計數相同，`forgeDraws` 不變。
- **不劇透的測試**：一千個種子 × 數個存檔情境（剛解鎖、第一波、全部上線、全部見過），每一則委託的目標都 `seen ≥ 1`（收購的素材「認得」），文字插槽填的名字都屬於見過的東西。

### 9.3 型別（`engine/guild.ts`、`engine/state.ts`）
```ts

type GiverId = 'anna' | 'marta' | 'glen' | 'orik' | 'doran';
interface QuestReward { gold: number; items?: Record<string, number>; rune?: string /* 'id@tier' */ }

  target: string;             // 敵人 id、素材 id，或地區 id（探路、掃蕩）

  reward: QuestReward; merit: number;
}
interface ActiveQuest extends QuestOffer { base: number; ids?: string[] /* 掃蕩凍結的物種 */ }
interface GuildState {

  offers: QuestOffer[];       // ≤ 5
  active: ActiveQuest[];      // ≤ 4（指名委託另計）
  merit: number;              // 0 … GUILD_MAX
  paid: number;               // 已發到第幾級的賀禮（0–4）
  viewed?: number;            // 看過哪一天的布告（「新」標記）
  intro?: true;
  personal?: Partial<Record<GiverId, 'active' | 'done'>>;   // PR E
  personalBase?: Partial<Record<GiverId, number>>;            // PR E：探路以外的基準
}

```

### 9.4 存檔
- `SAVE_VERSION` 維持 9（`save.test.ts` 的 `the save version stays 9`）。
- `isGuild(v)`：形狀檢查（整數非負、上限 `GUILD_MAX = 1e9`、種類與委託人在列舉內、`offers.length ≤ 5`、`active.length ≤ 4`、`paid ≤ 4`、`reward.items` 的值是正整數）。不合格就照舊算損毀（`loadGame` 的 `corrupt`）。
- `repairGuild(d)`：目標 id 不在 `ENEMIES`、`MATERIALS`、`REGIONS` 的委託丟掉；報酬裡不存在的道具丟掉那一項；`rune` 不合法就丟掉那一項（照 `repairBestiary` 與 `repairRuneFields` 的精神：資料改名不讓存檔壞掉）。

## 10. 經濟檢查（`engine/guild.economy.test.ts`）

照 `engine/forge/economy.test.ts` 的價值定義：素材以賣價計、裝備以 `max(賣價, 拆解精華的賣價)` 計。

1. **能交的貨只能打到**：`DELIVERABLE` 的每一個素材，`kind` 屬於 `monster`／`region`／`trophy`；不在店的商品（`ITEMS`、`EQUIPMENT` 的商品清單）、不是任何 `CONSUMABLE_RECIPES` 的產出、不是 `DISMANTLE` 的精華、不是任何鍛造、融合、製作的產出（鍛造只產裝備與消耗品，測試逐一列舉鍛造的產出種類確認沒有素材）。
2. **報酬餵不回委託**：每一種報酬素材（精華、稀有、碎片、歸還之燈、復活羽毛、符文）都不是能交的貨。唯一的例外是安娜的指名委託收「清晰的碎片」（一次性，`personal` 記一次），測試具名放過它，並斷言它只能完成一次。
3. **收購只付貨的錢**：每一個能交的貨 × 每一個 Q，報酬金幣 = `round(1.6 × Q × price)`，而且**不給素材**；所以「買不到 → 交貨 → 拿錢」的最大值是有限的貨乘 1.6，不能用錢換回貨。
4. **一則一次**：同一則回報兩次第二次失敗；放棄之後再接失敗；同一天再貼一次布告，`offers` 與 `active` 不變；回報之後那一則從 `active` 消失。
5. **賀禮一級一次**：升級發一次；讀檔、再回報、再升一次門檻不重發（`paid`）；`merit` 在上限停住。
6. **布告的上限**（寬鬆）：一千個種子 × 深度 1–60 的情境，一張布告所有報酬的價值合計 ≤ `BOARD_CAP(d) = 600 + 120 × min(d, 60)`。紅了就調 §6.1 的公式一次；還紅寫成具名例外（平衡不是優先）。
7. **沒有抽取副作用**：接下、放棄、回報、貼布告之後，`forgeDraws`、`story.pity`、`bestiary` 不變；`game.rng` 的計數不變（§9.2）。

## 12. 接口（不設計，只留位置）

### 12.1 採集
- 能交的貨由 `DELIVER_KINDS`（`data/guild.ts`）與 `knownMaterial(state, id)`（`engine/guild.ts`）兩處決定。採集上線時：新的素材種類（例如 `MaterialKind` 加 `gather`）加進 `DELIVER_KINDS`，`knownMaterial` 多一條「採過」的規則，委託人表加一列（希爾薇的芽、千鶴的小祠是 story-world §11.2 的候選地點，指名委託也可以掛在那裡）。§10 第 1 條的測試會自動檢查新素材也只能採到、不能買。
- `QuestKind` 預留 `'gather'`（不實作）。

### 12.2 NPC 立繪
- 委託人以 `GiverId` → 設施的 `art.npc` 鍵對應（§7.1）；立繪發布後詳細欄、回報的對話自動帶上（`lateArt`，不改程式）。若立繪項目改用 `NpcId` 為鍵，只改這張對照表。

### 12.3 難度限定裝備
- `QuestOffer` 預留 `tier?: Difficulty`：高難度懸賞以 `dungeon.bossKills` 的前綴鍵（`nightmare:mainline:25`）算進度（頭目已經有；守關者要另記，屆時設計）。
- `QuestReward` 預留 `special?: string`（裝備 id），回報時以 `rollItem` 的固定種子產生（屆時設計，不准從 `lootRng` 抽）。四燈與高難度懸賞是自然的門檻。

### 12.4 一趟之內的限制條件
- 預留 `QuestOffer.rule?: string`。要做的時候在 `Run` 上記、在 `toTown` 結算，而且要讓「`Run` 不存檔」的讀檔行為仍一致（重新整理就當這趟沒走過）。

### 12.5 好感度
- `remarks` 是唯一的夥伴接觸點。若之後要給好感，接在 `engine/story/bond.ts` 的既有入口、受 `BOND_SWITCH` 管，並重跑第 21 項的平衡帶；本文不做。

### 12.6 劇情美術
- 指名委託的完成對話寫成 `Written` 的形狀（`lines` 陣列，帶 `who`），之後要升級成有背景的場景，只要給它一個 `SceneId` 與 `at(PL.*)`。
